# 临时帆软 Portal 邮箱免登

帆软入口参数保持 `user_email`，值为邮箱的 32 位 MD5 十六进制摘要。帆软和后端使用相同规则：邮箱去除首尾空格、转小写，按 UTF-8 编码后计算 MD5。摘要大小写均可，示例邮箱 `user@example.com` 对应 `b58996c504c5638798eb6b511e6f49af`。

示例邮箱仅用于说明参数格式，不是可用于线上登录的账号。实际用户须由管理员在对应环境的权限表中配置，并按职责授予角色和数据范围。

前端在首次加载工作台之前接收 `user_email`，仅接受 32 位 MD5 十六进制摘要，保存到当前标签页并清除地址栏中的该参数。有效摘要自动请求后端匹配权限账号，有权限直接进入工作台。明文邮箱、空值、格式错误和重复参数会清除旧身份；没有参数时保留当前标签页的已有身份，支持刷新。用户主动切换账号时，可通过手工输入框提交邮箱。Demo 模式不受影响。

继续使用现有 `X-User-Email` API 链路。后端对手工邮箱按同样规则计算 MD5，再匹配 PG `data.user_permissions`。仅允许唯一匹配、已启用且角色有效的账号进入。匹配冲突会拒绝登录，后续请求继续检查账号权限。

部署沿用现有内部 UAT 的 `APP_ENV=development`，无需新增配置或表结构迁移。如果部署指向其他 PG，需在该库配置实际用户所需的权限。发布后用已授权的实际测试账号替换示例邮箱，验证其权限对应的页面、刷新行为及未配置邮箱被拒绝。

这是用户指定的临时邮箱传递方案。手工输入可通过下述开关控制；无论是否开启，URL 参数和 `X-User-Email` 请求头均无法证明访问者已通过帆软认证。仅适用于当前受控内部测试入口；不等同于可信 SSO。现有 `production` 环境仍拒绝此类邮箱身份，后续正式接入需替换为可验证的认证凭据。

## 测试邮箱输入开关

服务器修改 `/opt/shell-forecast/deploy/.env` 中的一个配置：

```dotenv
# true：允许手工输入邮箱登录；false：仅接收帆软传入的 MD5。
VITE_LOGIN_EMAIL_EDITABLE=true
```

未配置时默认 `false`。该值经 Compose/Dockerfile 在前端构建时注入，因此修改后需要重新构建发布，单纯 restart 不会生效：

```bash
cd /opt/shell-forecast
sudo bash deploy/deploy.sh --port 18080
```

本机开发使用 `frontend/.env.local` 中的同名配置并重启 Vite。两种模式均支持帆软带入 MD5 后自动校验并进入工作台；手工输入仅在提交时建立该标签页身份，后端继续检查用户权限。测试完成后把配置改回 `false` 并重新部署。

本版已移除旧右侧 Data Agent 嵌入模块；本文保留的邮箱登录和 Portal 认证不受影响。
