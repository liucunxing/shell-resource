# 全局表格统一与验收

日期：2026-11-15。范围为现有工程，延续用户已授权的 main、PG 测试、本地演示测试三分支同步。

## 最终行为

- 长表在容器中滚动，完整 thead 冻结；两层分组表头一起冻结，不使用固定行高猜测偏移。
- 表头加粗，数据、数字、表单控件居中；数字采用 tabular-nums，保留字段既有单位、精度和缺失显示。
- 所有数据列提供排序与方向提示，可用键盘 Enter 操作。操作、选择和仅用于打开详情的拆分依据入口不做无意义排序。
- 金额、占比、差额等使用原始数值，避免千分位、显示舍入、负号和缺失影响排序；缺失值始终在末尾。复合图形列指定排序值，组织图按投资占比、判断按当前 Vol/C3 口径的绝对偏离排序。
- 合计、矩阵参照、版本状态/归属说明、空态及添加行保持位置。React 行 key、编辑回调与对象关系保持不变。
- 经销商范围与原始数据先排序全部筛选结果，再分页，不改变占比分母。已有业务排序表使用 manual 模式，避免两套排序叠加。
- 经销商明细条数按用户最终修正为 **10 / 20 / 50 / 全部**，默认20；全部显示当前筛选结果。切换页数或条数回到表格顶部。
- 桌面保留经销商/金额固定列；640px以下仅冻结整个表头，所有列可横向滚动，避免固定列占满手机宽度。

## 覆盖范围

代码扫描覆盖 pages 中52处共享 React Table 定义，统一使用 shadcn Table 与 TanStack 排序。公共改动同时作用于保留页面；未将存档原型或未使用的旧 HTML 字符串渲染器当作当前应用页面。

## 验证结果

- `npm test`：64个测试文件、379项通过；新增公共表格回归覆盖负数/缺失、精度、输入值、分组坐标、分页与固定行。
- `npm run build`：TypeScript与Vite构建通过。
- `npm run check:bundle`：通过，ExcelJS仍只有Worker内一份，没有调整阈值。
- 浏览器记录覆盖57个表格状态、417个排序表头（含同一组件在不同角色/Tab下的检查）。
- Playwright在本地SQLite合成数据入口 `http://127.0.0.1:8019` 检查当前导航、Tab和抽屉。每个可排序表头都实际点击并用Enter切换；纯数字列检查显示数值顺序；检查所有单元格计算样式为center。
- 桌面1440×1000、窄屏390×844；两层表头滚动250px后位置保持不变；桌面横滚500px经销商列仍固定。手机页面无横向撑破，表格可横滚到末列。
- 每页10/20/50分别显示对应条数，全部显示123条；健康检查查看全部123家后表头冻结。
- 项目编辑态排序后修改预算仍绑定原Initiative；取消修改后重新进入，金额恢复，没有提交写入。

浏览器检查脚本、JSON结果和截图保存在本地 `output/playwright/global-tables/`（该目录不入Git）。包括 owner/admin/lead/management/editor/drawer/version/edit/viewport 检查记录，以及 `dealer-frozen-desktop.png`、`dealer-narrow.png`、`health-all-frozen.png`。

V20原型与工程以王磊Owner、经销商明细Tab、1440×1000进行对照：保留页内Tab与表格分组/列序；本轮按用户最新要求增加居中、排序、冻结和分页选择。原型截图 `prototype-dealer-desktop.png` 与工程截图分别留存；两边合成数据/费用授权来源不同，不以数值一致冒充真实对账，也不声称用户已完成视觉验收。

## 实现约定

新增表格使用共享Table即可获得默认冻结和排序；复杂组件或混合说明单元格提供 `sortValue` 原始值。分页使用Table的pageIndex/pageSize，或既有业务层先排序再分页后指定 `sortingMode="manual"`；不要只对当前页排序。非数据行使用 `data-sort-fixed`，合计优先放TableFooter。

本轮不更换经销商target来源，不修改后端业务数据与权限。分支推送、本地构建和服务器部署分别记录；本轮未部署远端服务器，也不将本地演示检查当作真实PG业务UAT。
