# Insight 综合体检与流响应验收（2026-10-20）

## 已确认的问题与修复

1. 综合体检提示词曾写“通常不需要额外正文”，但服务端要求有投入变化时提供独立复核正文。真实候选两次返回 `blocks=[]`，仅 summary/checks 提及变化，随后本地校验失败。供应商 Schema 现将 `required_findings` 按维度设为必填，解包成原公共 blocks，再执行原事实校验。
2. observed 结论曾仅引用值为 null 的 rules，触发本地拒绝。供应商 Schema 的非 limited 分支现只允许引用有值事实；缺失事实仍保留在输入中供说明限制。
3. 真实模型使用投资 JSON 中的数值字段占位符，旧代码只识别完整 fact ID。现只开放授权 investment 的 historical_actual、plan、delta、abs_delta、multiple 五个既有字段，绑定父事实；未知字段及未发送事实继续拒绝。整个投资 JSON 不用于正文替换。
4. 真实模型的编号列表 1/2/3/4 曾被当成业务数字，现只排除行首列表序号。金额、年份、百分比等事实数字仍校验；999 万元反例仍被拒绝。
5. Insight 摘要、正文、图表、表格、核对依据统一金额万元与 Yield 一位小数。无单位金额占位符默认带万元，兼容显式元后缀；原始事实、分组、差额和计算精度保留。

## “模型流不完整”调查结论

历史失败只有 ValueError 类型，缺少 finish_reason、请求 ID 与接收进度，无法追溯其确切原因，不能认定为输出上限或网络中断。

现分开记录 output_limit（length）、content_filter、提前 EOF、坏 SSE、内容 JSON 解析失败、HTTP/网络错误与失败阶段。日志只含技术诊断，不记录模型正文、业务输入或密钥。成功记录 metadata.attempts[].usage.response_diagnostics 保留结束状态、字节数、帧数、首 token 和耗时。

提前 EOF、坏 SSE、JSON 解析失败与网络中断，在原 60 秒总截止时间内最多重试一次，并换为普通 JSON 请求；结果仍须经过相同结构、引用和事实校验后才保存。length/过滤不重复发送相同请求。所有失败继续保留旧记录。

真实 Qwen 限额实验使用同一批 300 家合成输入，刻意设 max_tokens=8：

- SSE 返回 length、[DONE]、7 帧、23 字节内容，耗时 2.920 秒；分类为 output_limit，不重试、不保存。
- 普通 JSON 也返回 length，耗时 2.488 秒；独立诊断通过。
- 这是受控复现实验，不能倒推历史那次失败也是 length。

正常生成没有人为缩小 max_tokens，下面五次响应均为 stop 且收到 [DONE]，未发生截断。输出约 1,089–1,790 tokens，当前样本没有显示输出长度上限是正常调用的瓶颈。

## 最终真实模型验收

使用开发环境实际配置的 qwen3.8-flash，经实际 FastAPI Service 调用；数据库为新建隔离 SQLite，输入全为合成数据，无生产业务写入。历史为 2025 实际，本次为 2027 计划，属于跨年参考，不能称同比。

300 家完整比较数据留在证据/前端清单中；模型按已有投影策略接收 4,505 条事实中的 239 条代表事实，覆盖复核类型、最大变化和不同分组，不是把全部原始行直接交给模型。请求约 77.6–78.6 KB，约 2 万输入 tokens。完整 300 行、缺失与零区分、第 300 家大额变化和保存读回均通过断言。
