# Insight 两种方案生成失败调查（2026-10-21）

## 证据与原因

在用户授权账户的指定 Initiative 范围，线上两个生成接口均复现 HTTP 502。用户另行明确允许将该范围数据通过现有 Qwen API 做本地诊断回放；真实数据回放不写业务数据库。

1. **历史 Yield × 计划投入**：两次基线回放均收到 Qwen SSE 错误帧，代码为 `invalid_parameter_error`，类型为 `invalid_request_error`。供应商明确说明生成符合 response_format 的 JSON 时输出异常，因此主动中止。收到约 2 KB 内容、无正常结束标记。不能将这次错误归因为网络断流或输出 token 上限。
2. **分配结构分析**：完整生成的“甲、乙、丙分别占 x%、y%、z%”被旧校验器将三个值都绑定到丙，误报 `overview:unbound_number`。同两份原始候选在新校验器下通过，未修改原证据或候选。
3. 后续回放还发现输入选择问题：7 家当前分配对象与 410 条授权历史比较记录共存时，缺历史样例占用了选择名额；图表预览仍显示被省略对象，模型引用其事实却被拒绝。
4. 模型也曾自行合计未提供的前三家占比、分组数量，或写错公司名称。这些不是校验器误报，仍然拒绝；通过简短逐维事实提示和明确的修复指令减少发生。
5. `Yield 5.6倍` 去空白后曾从小数尾数开始匹配，造成数值误报，现按完整数值识别。同时增加完整当前队列的缺失断言校验：当每家历史 Yield 都有值时，不能写“部分经销商无历史 Yield”；0 是有效值。

## 修复边界

- 四象限多次实测发生结构化解码中止，现默认直接使用非流式 JSON Object，避免每次先耗费十多秒等待失败；其他方案继续 Schema 模式。两种模式生成完全相同的授权 wire Schema（含必填复核正文），JSON Object 将其作为提示保留，后续仍执行全部本地校验；可显式指定 Schema 做诊断。
- 其他方案遇到已证实的供应商结构化输出中止类型，在原 60 秒总时限内最多一次改用非流式 JSON Object；未知参数错误不触发此恢复，部分流内容不作为结果。CPU 校验和重新核对授权后再次检查截止时间，超时不进入保存。
- 有序“分别”句式按对象、指标和顺序逐项校验，交换比例/金额、漏引用、错误数量继续拒绝。仅对有对应证据的缺失说明、全局预算陈述和零项复核陈述消除误报。
- 小范围完整保留当前分配对象，并为独立风险保留名额；缺历史样例靠后。模型预览过滤未发送事实对应的对象，服务器完整图表不裁剪。
- 为模型提供来自本次已发送事实的短句和引用作为写作起点，明确 0 值与缺失的区别；复核维度仍必须由模型展开实际变动，不以普通短句覆盖必显复核正文。
- 金额仍统一万元，Yield 仍为一位小数；没有放宽事实校验。没有数据库迁移。

JSON Object 与 JSON Schema 模式的差异参见[阿里云结构化输出文档](https://help.aliyun.com/zh/model-studio/qwen-structured-output)。本次恢复的有效性以真实 API 验证为准。

## 日志可定位性

旧版本有错误类别和流进度，但没有跨页面、生成阶段和供应商调用的统一问题编号，也未提取该错误帧的具体类型；仅凭截图无法找回准确请求。本次尚未取得旧服务器日志，原始截图对应的请求不能被断言为已经从日志追溯。

新版本页面显示问题编号，服务端按同一编号记录方案、年度、范围/用户哈希、阶段、供应商请求号、结束原因、接收字节/帧数、耗时、重试和具体校验失败路径。供应商错误正文、模型正文、业务输入、邮箱与凭据不写入诊断日志。未知异常转换为安全 HTTP 错误，避免 ASGI 再抛出后被服务器打印原文。

运行日志按 10 MB × 5 轮转；部署替换前归档当前保留的旧容器日志到受限目录。不是按天永久保留，不能恢复此前已被删除的日志。查询方法与保留边界见 [服务器运维手册](SERVER_OPERATIONS.md#insight-问题编号与日志保留)。

## 验证记录

真实数据和完整模型请求/候选仅保存在本地忽略目录 `output/insight-20261021/`，不进入 Git 或镜像。匿名回归覆盖原错误形态及反例。

300 家合成经销商实测使用真实 qwen3.8-flash 和隔离 SQLite，覆盖第 300 家变化、零与缺失、万元显示、必显复核、保存读回。`synthetic-300-final` 三方案均 HTTP 200（32.307、39.879、31.819 秒）。四象限真实触发结构化输出中止，自动恢复后通过；不是注入错误或仅模拟恢复。
