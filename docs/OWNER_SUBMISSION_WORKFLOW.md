# Owner 提交与退回（2026-11-16）

Owner 可直接提交，客户端在同一次操作内先保存当前输入，再用服务器返回的修订号提交。保存失败不提交；保存成功但提交失败时保留草稿并提示错误。重复点击受请求锁保护。

部门确认前：提交后仍可编辑；保存新草稿会使当前项目退出齐交状态，直到再次提交。历史提交快照保持不变。

部门确认后：Owner 锁定。Admin 从“部门方案退回”选择部门并填写原因，退回部门负责人；此时所有 Owner 继续锁定。部门负责人可退回全部、按 Owner 或逐项退回，只有明确退回范围开放编辑。重新提交后等待下一次部门确认。

数据库升级至 `20261116_01`，新增 `initiative_workflows.owner_edit_locked`。迁移保留既有确认及确认后仅撤回的锁定状态；明确退回的项目开放。版本关闭、截止、身份和修订冲突限制继续生效。

验证：57 项后端相关测试、429 项前端测试、Ruff、Mypy、构建、bundle 检查通过。本地独立 SQLite 合成环境的浏览器直接提交依次返回 draft 200 / publish 200，提交后仍可编辑。另一个 session 的自适应改动 `e01e8d7` 已包含在 main，浏览器覆盖见 VIEWPORT_COMPATIBILITY.md。真实业务数据不用于提交/确认写入测试。
