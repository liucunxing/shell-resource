## 规划与协作

| 范围 | 当前要求 |
|---|---|
| Owner | 三步完成经销商与其他预算拆分；草稿可暂不平衡，正式提交必须平衡；版本开放时，部门提交前可反复修改并重新提交，以最新提交覆盖当前方案；首次、继承上版、重复及批量提交均无需填写变更原因，调整依据说明选填；部门确认后冻结；部门撤回或管理员驳回后直接恢复编辑 |
| 部门负责人 | 当前部门全部 Initiative 提交后才可确认；版本开放才能提交／撤回；撤回解锁本部门全部 Owner 并保留提交；取消定向退回步骤 |
| 管理层 | 分配与分析只纳入部门已确认快照；预算仍可见，不能把未确认草稿计入组合 |
| 规划版本 | 独立创建；启用时自动停用其他版本，全局最多一个启用版本；管理员可随时停用，保留原方案、提交、部门确认与可见范围；新版本只复制最后提交快照，不复制未提交改动，版本间状态隔离 |
| 对比 | 保留来源版本与当时SD/RSM归属；退出组织保留减少金额。V20组织页“较上版”显示带符号万元，不用百分比代替 |
| 经销商名单 | 可从当前业务线的 Active 经销商库勾选到方案，新增分配行金额为0，不创建主数据；已选名单独立显示。纳入零投入经销商，跨 Initiative 按对应身份去重；检索、排序、分页不改变历史比较分母 |
| 其他预算 | 受保护原因保持固定；停用不删除已有金额，自动找平不能改写人工理由 |
| 用户权限 | 所属组织与业务授权范围独立；费用明细按所属部门大类上限，再以部门/用户配置收窄。角色不扩权，缺有效归属不提供明细；完整历史总额、Yield、占比公开 |
