# Dashboard Target 空值排查

2026-11-18：管理层资源大类详情的 Target 空值有两个独立原因。

1. 本机 8020 预览进程仍运行 2026-11-15 加载的旧后端，源 `sourceTarget*` 有值，但展示用 `contract*` 和 `phasing*` 被旧批次确认门控清空。磁盘代码已修复不代表进程已加载；重启本机预览后，真实 API 与当前源值投影一致。此操作不代表服务器部署。
2. 详情 `historicalDetailTotals` 使用完整合计：当前范围任一业务身份的 Target 缺失，就不返回完整总额。源 NULL 仍须保留，不能补零或跨年份借用。

2026-11-18 用户后续确认覆盖上述完整合计展示方式：详情 Target 直接加总有效值，部分缺失时数字旁标 `*`，鼠标悬浮或键盘聚焦显示“统计口径291/379 家，数据不完整”（数量按实际范围动态计算）。移除常驻缺失说明与另列小计。全部缺失显示“—”并提示 0/全部家数；零和有限负值正常计入有效值。单位仍为源 L、展示 KL。

范围沿用当前已确认项目的经销商名单，按 Sector 与经销商身份去重，包含已选未获配对象。搜索和分页不改变覆盖或小计。期间切换使用对应年度字段；Phasing、Yield、费用权限和其余完整合计不变。

同轮界面调整：版本变化页搜索输入框的 flex basis 改为 auto，避免在纵向 Label 中被 280px 的基础尺寸撑高；保留 280px 宽度与 32px 高度。管理层和部门负责人版本变化 Initiative 表格均移除 Owner 副文本和表头标注，搜索同步只匹配项目/维度名称。

后续调整验证：最终代码 442 项前端测试、构建和 bundle 检查通过。浏览器验证两期 Target 有效值合计及星号提示，鼠标悬浮和键盘聚焦可读；管理层与部门负责人版本变化表均无 Owner 副文本，搜索框均为 280×32px，项目名称筛选正常，390px 窄屏无页面横向溢出。仅本机预览验证，推送不部署。
