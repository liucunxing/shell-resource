# 管理层 Sector 数据权限

管理层保留只读角色，由管理员显式配置1–4条业务线。所属 Sector/Department 与业务授权独立；配置全部四条仅代表当前四条业务线。旧账号空范围继续保留，但读取返回403。不存在从所属组织推断或空值代表全部的回退。

预算、已确认分配、历史指标、经销商目录、单项目快照、下钻、版本对比和导出使用同一范围。跨 Sector 同编码仍按 `(sector, id)` 业务身份统计。历史费用列继续按所属部门上限收窄。管理层不能编辑分配，未确认分配不能进入分析。

`GET /identity` 返回现有工作台身份结构，使用普通入口、Portal和模拟查看的有效身份依赖，禁止缓存。前端每10秒及切回页面时探测身份；发生范围变化清空页面与目录、使旧请求和异步导出失效，再读取新范围。Portal 延续权限指纹变化后重新进入的要求。版本列表仅保留共享规划版本元数据；版本内业务数据始终裁剪。

## 迁移与发布

Alembic `20261123_01` 替换 `ck_user_permissions_role_sector_count`，允许管理层0–4项；0项用于保留未配置的旧记录，应用新建/修改要求1–4项。迁移不修改任何账号授权、快照或分配数据。未知值、NULL元素和重复Sector被数据库约束拒绝；旧未验证记录也由每次请求校验。DDL锁等待上限2秒。

1. 发布前准备经确认的管理层账号→Sector清单，暂时关闭管理层入口并结束旧会话。
2. 核对目标数据库和当前Alembic revision，在隔离schema演练后升级迁移并更新前后端。
3. 管理员按清单保存授权；先模拟查看，再逐账号验证真实入口和业务范围。空授权账号保持禁止访问。
4. 确认PCMO、多Sector、空授权、旧版本、版本对比和权限收窄后开放入口。

回滚先关闭管理层入口并结束会话。迁移downgrade在存在非空管理层授权时主动拒绝，避免静默丢弃授权；只有保存授权清单、显式清空授权后才能退回旧约束。旧代码会全量放行管理层，回滚期间必须保持其入口关闭。

## 验证

后端权限API测试覆盖普通身份/管理员模拟、单/多/全Sector、空/非法授权、跨Sector同编码、预算与已确认快照、直接ID越权、旧快照及版本对比。前端覆盖配置/Excel校验、范围展示、版本修订不变时收窄范围、403清空数据、延迟返回丢弃。运行项目要求的pytest/Ruff/Mypy和前端测试/构建/包体检查。

真实PostgreSQL演练命令（须明确核对目标数据库）：

```powershell
.venv/Scripts/python.exe scripts/verify_management_scope_pg.py --expected-database resource_studio --report .cache/management-scope-pg.json
```

脚本在随机schema复制用户表结构，仅插入合成账号，执行真实迁移和ARRAY约束正反例、回退保护及往返升级，最后回滚整个事务并检查schema已清理、业务Alembic revision未变。没有业务schema应用选项。真实身份登录和上线账号授权须在发布时单独验收。
