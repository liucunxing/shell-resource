# 业务旅程验收

从当前应用的验收输入定位用户、业务旅程、案例预期和测试数据。业务动作须通过本轮临时应用的页面发起，各身份独立登录同一份临时业务数据库。运行权限仅覆盖隔离副本和本轮报告。对共享应用、权限、数据、部署和源码只读。记录缺陷，由业务与开发另行处理。

## 在资源投资工具运行

从仓库根目录阅读 [业务输入](../../../uat-inputs/resource-studio/README.md) 与 [运行说明](../../../tools/business-uat/README.md)。使用部署记录的 Git SHA。已有获准使用的站点根地址时可一并传入，只读核对健康状态及前端入口文件。

```sh
node tools/business-uat/cli.cjs --revision <部署提交SHA>
```

未提供部署 SHA 时，可以运行当前检出，明确记录为本地版本。指定已获准使用的脱敏全员名单时传入 `--roster`。默认使用仓库内的合成人员。使用同一抽样参数复测已知问题，扩展探索时另跑一个参数并留下记录。

## 读证据和汇报

1. 打开命令输出目录的 `index.html`、`results.json` 和关键截图。核对名单分母、逐人职责、跨部门交接和管理层金额。真实用户登录与部署数据库口径需要相应现场证据。
2. 实际查看至少三个已留证的业务时刻，包括预算未配平、部门尚未齐交和撤回后的管理层视图。站在该角色的位置，记录页面显示的提示、可见金额、下一步能否判断、是否需要来回找人或找项目。证据不足时写明所缺页面或用户反馈。
3. 在本轮输出目录将审阅结果写入 `ux-review.json`（格式见运行说明），执行 `node tools/business-uat/ux-review.cjs <本轮输出目录>` 合并到同一页报告。发现问题时给出角色、现象、影响和最短复现路线。
4. 用业务语言汇报结论、覆盖人数、需要处理的事项和未测范围，附首页链接。首次失败记录要保留；复测另开一轮。核实用户确认的新场景后，可在独立的维护任务中将场景加入应用验收包。

## 推广到其他应用

沿用逐人清单、同一笔业务在多角色间流转、固定预期与可复现抽样、隔离写入、业务报告这套方法。为新应用提供自己的用户与项目归属、正常和折返路径、可独立计算的预期结果、合成数据、页面动作和副本启动方式。第一次接入时用团队已知的缺陷和修复版本校准同一案例，并核对该案例会在何种条件下标为未测。
