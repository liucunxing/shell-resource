# 资源投资规划工作台 V1.3

依据客户 `资源投资规划工作台_V1.3.html` 重构的独立 React 前端。业务页面和交互在 `frontend/` 内实现，使用本地演示数据；尚未调用后端接口。

## 运行

使用 Node.js 22.12+ 或 24：

```powershell
cd frontend
npm ci
npm run dev
```

开发地址为 http://127.0.0.1:5173 。检查与生产预览：

```powershell
npm test
npm run build
npm run preview
```

预览地址为 http://127.0.0.1:4173 。`dist/` 可部署到静态服务器。页面导航使用 React 状态；刷新返回默认 Marketer 工作台，本机业务数据保留。

## 页面与业务规则

| 角色 / 页面 | 行为 |
| --- | --- |
| Marketer / 我的工作台 | 仅展示本人 Initiative，搜索筛选，查看预算、其他预算和同步情况 |
| Initiative 拆分 | 金额与比例联动、增删经销商、历史占比填充、动态其他预算、Excel 导入导出、一键找平、保存草稿和重复同步 |
| 部门总览 | Marketer 查看部门汇总；负责人查看本部门工作稿与只读详情 |
| 管理层统览 | 汇总各 Initiative 最新同步快照；三部门与总计卡片、四维筛选、可排序明细、只读 Insight |
| 管理后台 | 预算和 Owner、其他预算原因、参考数据批次、角色说明、指引版本、审计；Excel 差异预览与确认导入 |
| 原始数据 / 数据口径 | 角色范围内的预算、历史和来源说明；明确年份、金额单位与演示假设 |
| 执行追踪 | 按 V1.3 保留入口，尚未实现执行数据接入 |
| 右侧工作栏 | 历史参考、协作反馈、六点 Insight、小One问数Agent；展开后与导航、主工作区组成三栏 |

每项 Initiative 持续编辑并独立同步；同步后仍可修改，也可再次同步。管理层只读取最新同步快照，未同步草稿不会影响管理层汇总或分析。工作稿允许暂时不平衡，正式同步时检查预算平衡与其他预算说明。界面无部门审批、退回或终态锁定步骤。

金额支持两位小数。其他预算使用动态原因行，默认包括新增经销商预留、无法分配到经销商、其他支出。停用原因不会删除已有金额。一键找平只调整专用的“无法分配到经销商”自动行，不改经销商或手工其他预算；无法吸收超额时整项拒绝。

管理层明细的“占部门预算”始终使用该部门全部已同步预算作为分母；筛选只改变明细与分布条，不改变部门卡片。Insight 为六点固定规则模拟，显示事实与复核提示、分析范围、提示词版本和待更新状态，不调用模型。

## 数据与本机保存

- 沿用 V1.3 同源演示数据：75 项 Initiative、600 条分配、60 个经销商编码，总预算 6,402,000。角色、Owner、场景调整为演示配置。
- 金额单位尚未确认，按源表原值展示，不标为元。2024、2025 为全年；2026 为 1–8 月累计演示假设，不直接做同比或默认年化；不生成 2027 Vol / C3 预测。
- 历史整体 Yield 使用 2025 同年 C3 / 总资源；各角色共享整体比值，资源明细仍按范围展示。无有效分母时显示缺失。
- 新数据保存到 `shell-resource-workbench-v13`。可迁移同域原型 `resource-workbench-v13-20260919` 的兼容结构；旧工作台 `shell-resource-workspace-v1` 保留，不自动转成新版业务数据。
- 切换演示场景需确认，会替换当前 V1.3 本机工作稿、配置、同步与分析记录。刷新页面保留已保存业务数据；问数会话只保存在当前页面会话。
- 角色切换用于演示前端范围隔离，不代表企业认证、服务端权限或多人协同。

## Excel

Owner 和管理员分别使用当前页面下载的 `.xlsx` 模板。读取后展示校验结果与差异，确认后才写入；取消不写入。有错误时禁止确认，过期预览须重新导入。Owner 模板限定当前 Initiative，经销商标识与结构字段不可任意替换；管理员模板用于预算及 Owner 配置，不能覆盖经销商分配或同步快照。具体可编辑字段和限制随模板说明提供。

ExcelJS 在第一次导入、导出时加载；构建对这一解析包有大文件提示，首屏不加载该包。

## 小One问数Agent 二期接入

未配置地址时提供明确标注的本地场景模拟问答，包括会话记录、输入草稿和只读页面回跳；不生成 iframe，不调用真实问数服务。

复制 `.env.example` 为 `.env.local`，填写 `VITE_YIWEN_IFRAME_URL`，重启开发服务或重新构建后，即改为 iframe 产品界面。这个配置是浏览器可见的公开 URL，不可放密钥或认证 token。允许 HTTPS，以及 localhost / 127.0.0.1 / [::1] 的 HTTP 调试地址；拒绝用户名、密码和其他协议。

桌面（宽度 ≥1024px）采用左导航 / 中间工作台 / 右侧辅助区三栏布局。辅助区宽度为 320–380px，所有工具均停靠右侧，中间工作台保持可见和可操作；收起后恢复主工作区宽度。不再提供覆盖主工作区的最大化模式。较窄屏幕使用遮罩抽屉，手机全屏，支持 Escape 收起与焦点返回。

iframe 首次打开时加载，折叠、工具切换和业务切页保留实例；切换角色、演示场景或整页刷新时重新初始化。当前不向 iframe 传预算、身份或 `postMessage` 数据。真实服务的 CSP、登录、Cookie 与权限映射需二期联调；iframe 的 load 事件不等于产品已登录或可用。

## 工程与来源

- `src/workbench/pages/`：React 业务页面，按页面延迟加载。
- `src/workbench/WorkbenchContext.jsx`：角色、状态、本机保存与导航。
- `src/workbench/WorkPanel.jsx`：四个辅助工具与 iframe 接口。
- `src/workbench/domain/`：从 V1.3 模块迁入的计算、规则、演示数据及 Excel 适配，改为 ES 模块。
- `tests/v13/`：原型的六类规则回归；`tests/yiwen.test.ts`：22 项嵌入地址校验。
- `prototypes/资源投资规划工作台_V1.3.html`：客户原型原样副本，SHA-256 为 `1F359D3F0883B2BC3E3912CD30C314896D43EAEC32A9A6BC2A44EF565C10F434`。
- `VALIDATION.md`：本次构建、业务与浏览器验证结果；`output/` 为不入 Git 的本地证据。

外层为 React / TypeScript / Vite，V1.3 业务组件与规则为 JSX / JavaScript；启用 allowJs，未对迁入 JavaScript 声称完整静态类型检查。保留 Fluent UI Provider 和 Phosphor 图标。按 design-taste-frontend 的保留式改造方式沿用 V1.3 Shell 红黄视觉，优化列表宽度、紧凑表单、导航和手机布局。原型 HTML 自身保持原样并随构建复制，新应用不嵌入该 HTML。
