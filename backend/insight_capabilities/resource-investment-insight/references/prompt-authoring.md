# 提示词可以独立编写

本包固定的是可核对的数据边界与前端所需的接口，分析文案仍由提示词和模型决定。

## 直接修改的位置

| 文件 | 修改内容 |
|---|---|
| `prompts/common.md` | 共同的分析原则、表达要求、证据边界 |
| `prompts/comprehensive.md` | 综合体检的分析任务与示例 |
| `prompts/quadrant.md` | 四象限的观察方法与解读侧重点 |
| `prompts/structure.md` | 资金去向、集中和叠加的观察方法 |

`InsightPack.compile()` 每次都重新读取公共提示词和所选方案，包括同一个 Python 对象连续调用的情况。没有写死在代码里的报告段落，也没有提示词缓存。修改后再次生成请求即可测试；不需要重新构建前端或修改 Python。

`preview.html` 展示人工编写的结果样例，不会执行提示词。修改提示词后离线预览不自行变化是正常的：先重新请求模型，再用 `python scripts/build_preview.py --evidence 本次证据.json --result 本次结果.json --output out/model-preview.html` 校验并渲染该结果。不要把内置离线演示当作提示词沙盒。

## 可自由调整

- 标题、业务用语、解释角度、例子、读者关注点、详略和语气。
- 发现顺序、将同一对象的多个维度合并、通常展示多少重点。
- 在当前方案已允许且有数据的图形之间选择；有价值才配图。
- 正常情况直接总结，`blocks: []` 合法；有问题时可以展开更充分的解释。

“通常少量重点、摘要简短”是表达偏好，不是强制一项几句话的模板。JSON 字符上限是避免异常响应撑坏页面的容量保护：正文最多4000字符、最多32个内容块，不是要求写满，也不是旧版220字限制。

## 需要一起调整的情况

| 变动 | 需要同步 |
|---|---|
| 增加新图种 | manifest允许清单、Schema、渲染组件、样例与校验 |
| 增加字段或改字段名 | 结果契约版本、解析器和前端 |
| 改Yield、分母或象限分界 | 后端计算、证据版本与口径说明 |
| 放开更多数据 | 宿主权限查询；提示词不能代替授权 |

不要通过修改提示词来要求模型自行生成坐标、绕过必显超额、把依据不足写成正常，或执行未经允许的操作。这些属于数据与产品约束，不属于措辞限制。

## 版本与实验

1. 在独立目录编辑提示词，运行 `request` 检查最终消息是否包含改动。
2. 对比同一批证据；不要一边改提示词，一边换数据，又同时换模型。
3. 本地结果记录保存实际 `prompt_sha256`、`schema_sha256`、`evidence_sha256`、方案版本、数据版本、模型和思考模式。
4. 对客户发布时更新 `manifest.json` 对应方案版本；旧结果保留旧版本，不自动重写历史。

普通客户界面仅选择已发布的分析方案，不开放任意提示词输入。本地开发者和方案维护者仍可直接改这些 Markdown 文件，不需要让最终用户了解提示词。

## 测试能确认什么

离线测试验证：同实例重新读取、提示词变化导致摘要哈希变化、修改一个方案不会污染其他方案、正常内容可为空、长于旧220字的解释仍可通过结构校验。

它不能证明某条新提示词一定改善Qwen的业务判断。真实效果须用 `references/evaluation-cases.md` 的同证据测试记录比较。结构通过、引用存在，也不等于自然语言解释完全正确。
