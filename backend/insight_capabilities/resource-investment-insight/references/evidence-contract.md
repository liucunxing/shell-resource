# 证据与结果契约

输入标准见 `schemas/evidence.schema.json`，输出标准见 `schemas/result.schema.json`。样例均是显式标记的合成数据。禁止拿示例坐标当作客户数据。

## 输入由宿主后端提供

- `scope`：后端根据身份解析的范围标识、显示名称和角色；不是客户端传入后就可信的授权凭证。
- `planning_year / data_version / provenance`：区分计划年份、事实快照及真实/合成来源。
- `facts`：可引用事实，包含稳定ID、值、单位、时期、出处和必要说明。缺失值为 `null`，零为 `0`。
- `datasets`：已授权、预计算、符合图种要求的数据；没有足够数据就省略相应数据集。每个数据集必须绑定当前 `scope.id`，并引用已有事实。
- `check_constraints`：六个维度的允许状态、原因与可选 `required_focus`。这些是后端证据可支持的范围，由维护者/程序生成，不交给最终用户随意指定。

整体历史 Yield 可以作为当前 scope 被授权读取的汇总值，`dataset.scope_id` 仍标注当前 scope。不要为了解释 Yield 再附上未授权的跨部门资源分母或明细。

## 六维状态

| 值 | 含义 | 使用条件 |
|---|---|---|
| `review` | 需关注，值得复核 | 有具体证据支持复核方向；不等于判错 |
| `clear` | 在当前口径下暂无突出事项 | 必要证据与业务规则已提供；金额平衡只覆盖金额检查 |
| `observed` | 事实已核对 | 可以陈述数值，但没有正常/异常阈值 |
| `limited` | 待补充信息 | 缺少数据、目标、规则或权限 |

不要把最低Yield固定当成异常；已有历史Yield与计划金额时使用 `observed` 陈述事实；缺少未来目标只限制未来收益或投入合理性结论，在末尾说明，不使已有事实分析变成 `limited`。集中度未给阈值可标 `observed`，不能凭较小占比自动写正常。

对预算超额等必显事项，宿主设置 `required_focus: true` 且允许 `review`。结果必须在六维检查和正文内容块都显式呈现。零重点偏好不能屏蔽它。

## 图表数据

共同字段是 `id, kind, title, scope_id, unit, period, note, fact_ids, rows`。

- `comparison / ranked_bar`：行包含 `id,label,value`，金额为非负有限数。排名可带 `denominator`。若只展示选定对象，标题与说明必须明确，不能冒称全量TopN。
- `composition`：除上述字段外提供正数 `denominator`，各部分互斥、可加并与分母相等。预算不平衡时不要把总安排强制缩成100%；使用“预算 vs 已安排”比较，并显示差额。
- `quadrant`：每行 `id,label,x,y`，可带由上游确定的 `group`。x/y各提供 `label,unit,period,cutoff,cutoff_method`；提供 `population_count,excluded_count,cohort_label,cutoff_note`。中位数必须按完整入图队列计算，不能仅取画面中的TopN。边界值保留边界身份，不偷偷归为高/低。少于4个入图对象或某轴无差异时，本版本退为表格；这是展示条件，不是业务风险阈值。
- `table`：`columns` 提供 `key,label,unit`，每行只包含 `id` 与这些列；缺失单元格保留null。

单位约定：`CNY` 金额元、`ratio` 小数比率（0.0477显示4.77%）、`multiple` Yield倍数、`count` 个数，空字符串用于名称等文本。不跨列复用格式化规则。

四象限默认观察历史整体Yield与本范围未来计划投入，两轴年份与资金范围不同，应在图上明确。它是相对定位，不是未来ROI估算。若客户希望同年投入效率分析，应另给同年同口径数据及方案版本。

## 输出与渲染

`headline / summary / blocks / checks / limitations` 为展示内容。`blocks` 长度可变，三个种类为发现、图形与说明。模型只选择数据集ID，不返回坐标或图表配置。一个发现可关联多个维度；六维摘要的覆盖由 `checks` 独立保证。

图表数值直接来自原始证据；文字通过文本节点渲染。查看依据时展示关联事实的单位、时期、来源和说明。共同限制可以归并，但改变某张图含义的口径必须留在图旁。

已引用 `dataset_id` 的内容块可依据该数据集具体行解释对象与坐标，行明细是证据的一部分；`fact_ids` 同时标明该发现使用的汇总事实、业务规则或目标。未引用数据集的独立正文不能借用未关联图表的数值，宜由上游为关键对象提供可独立追溯的事实。引用存在只是可追溯性条件，数值解读仍需业务验收。

## 验证边界

脚本验证结构、ID、引用、scope一致性、状态约束、必显事项、构成分母、四象限数量与中位数等确定性条件。它不替代身份鉴权、后端SQL过滤、业务规则确认、原始数据审计，也不能通过引用ID证明每句自然语言都合理。生产接入必须保留这些宿主责任。

图表关联结果必须与所引用数据集至少共享一个 fact_id；主题和对象仍须人工复核，引用交集不自动证明文字与图一致。
