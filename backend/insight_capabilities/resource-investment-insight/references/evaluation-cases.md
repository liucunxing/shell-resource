# 验收用例与真实模型对比计划

## 本地验收边界

`examples/` 是人工编写的合成证据和预期输出，用于验证契约、提示词编译及可视化。通过自测不代表 Qwen 已实测，也不代表模型能稳定生成这些结果。默认测试无 API、无网络、不读取工程配置或凭据。

在能力包根目录执行 `python -m unittest discover -s tests -v`。需要 Python 与 `requirements.txt` 中依赖。测试不修改共享提示词；提示词编辑实验仅操作临时副本。

覆盖四类证据 × 三种方案：关注案例、无突出事项、依据不足、预算超额。验证六维唯一覆盖、预算必显、金额口径、构成图分母、象限中位数与样本数、缺失与零区分、范围和引用、非法结果拒绝。另验证同一实例立即读取新提示词、单方案修改隔离、正文超过旧 220 字限制、零个或多个内容块，以及模拟 HTTP 错误不泄漏凭据。

金额计算与授权过滤属于宿主责任。当前测试独立核对样例预算恒等式与头部占比分母；不能据此宣称任意事实文本都被自动验真。授权范围标签校验同样不能替代宿主真正的数据权限过滤。

## 后续真实模型评估：先批准预算，再调用

由负责人先确认脱敏样本、模型与区域、每组调用次数、思考模式、超时、最大输出 token、总费用和总耗时上限。没有预算与环境确认不启动真实调用；不能使用其他项目现存密钥作为默认凭据。

建议取至少 20 个有业务复核答案的案例，在相同证据和方案下比较 Flash 普通模式与 Flash 思考模式；必要时再增加更强模型。保留模型标识、提示词和证据哈希、原始合规结果、校验失败原因、延迟与 usage；不保存密钥。记录产品交付使用的是原始输出还是经校验后展示的结果。

| 案例 | 应当观察到 | 不应出现 |
|---|---|---|
| 预算超额，其他图形信息很多 | 所有方案显著保留超额金额和复核方向 | 100%截断、构成图伪装平衡、重点被压掉 |
| 缺少历史或未来目标 | 明确区分可核对金额与不能判断的事项 | 缺失补零、正常通过、未来收益预测 |
| 高低 Yield 排名但无业务阈值 | 相对位置和待补业务依据 | 自动认定过度投入或要求增减金额 |
| 历史与计划跨年度 | 年份和实际/计划属性清楚 | 把2027计划比2025实际称为同比 |
| 多 Initiative 同一经销商 | 合并讨论、解释需核对用途 | 把叠加直接认定重复投资 |
| 目标和规则齐全且通过 | 简短六维摘要，可无重点块 | 为凑篇幅制造风险或六段长文 |
| 整体历史 Yield 授权只读 | 使用授权汇总，保留口径差异 | 推测跨部门明细或扩大权限 |
| 象限坐标相同、可比样本不足 | 降级明细表或说明不足 | 编造坐标、强行象限分类 |
| 零金额、负增长、非零其他安排 | 合适的金额/构成/趋势图与标签 | 将负增长画作负金额、其他安排算作到经销商 |
| 提示词换视角但证据不变 | 重点与表达可以变化，事实与约束一致 | 旧缓存、数字改变、强行同一段落模板 |

## 评价维度

业务评审逐例标注：优先事项是否有决策价值、是否漏掉必显问题、误报是否严重、证据是否支持标题、图形是否比文字更清楚、正常内容是否足够简短。结构通过率只是一项工程指标，不替代这些人工判断。

发布门槛应由客户或产品负责人确认。建议把编造金额、跨范围泄漏、预算超额遗漏、缺失判正常列为阻断项；出现任何一次先分析原因和修复，再扩大测试。比较模型时同时报告错误类型、延迟分布、费用和人工评分，不只展示精选成功截图。

可视化人工检查至少包含宽屏、右侧窄栏、长名称与手机宽度；检查文字可读、坐标与金额不截断、图例和数值非仅靠颜色区分、键盘可操作、六维摘要持续可见。预览的人工结果需要明确标识“合成演示”，不能冒充实时模型输出。
