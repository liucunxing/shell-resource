# 分析方法与提示词维护

本文件面向接入和维护人员。公共提示词规定事实与接口边界，各方案提示词规定分析目的；这里解释需要由工程侧先准备的计算口径。方案文字可独立修改，不需要为了调整语气、重点或展示偏好修改模型调用代码。

## 三个方案与六维检查

| 方案 ID | 主要问题 | 优先可视化 | 六维检查 |
|---|---|---|---|
| comprehensive | 当前先看什么，为什么 | 根据实际发现选择对比、构成或短表 | 全部显式显示 |
| quadrant | 历史 Yield 与计划投入相对位置如何 | 有效四象限散点图 | 全部显示，其余维度不因方案切换而隐藏 |
| structure | 预算流向哪里，集中在哪些对象或用途 | 构成条、排序条形、其他安排短表 | 全部显式显示 |

六维是检查覆盖，不是强制六段长文。checks 恰好六项；正文 blocks 可按发现合并、排序、增减，没有实质发现时可以为空。正文数量不应由 UI 固定为三张卡或六张卡。

## 四象限口径

1. **横轴：历史整体 Yield。** 当前业务参考为 2025 全年 C3 / 2025 全年整体资源。必须由后端计算并标注来源、时间范围、分母。整体 Yield 可只读，但其构成明细仍受部门权限限制。
2. **纵轴：计划投入。** 当前参考为 2027 年该用户授权范围内分配到某经销商的计划金额。不要把无法归属具体经销商的其他预算安排塞进散点；其金额在结构分析单独展示。
3. **可比样本：** 由上游在权限范围内明确行业、对象、数据完整性和计划范围等筛选规则。整图金额必须使用同一授权范围和单位；不同权限范围的图不能直接比较象限人数或坐标高低。权限不足以建立有效可比样本时不输出误导性的完整四象限。
4. **分界：** 优先使用经客户认可的业务标准，并携带版本或说明；未配置时可用可比样本中位数作相对分界。中位数不代表投资达标线，图上应显示“样本中位数分组”，分析文案不得换成风险阈值。
5. **归属：** 后端计算象限及边界状态并提供给模型、渲染器。建议相等值标注为“位于分界线”，不要靠浮点舍入把边界对象写成明显高 / 低；若现有实现使用明确的等号归属规则，应在数据集元数据中给出且前后端一致。

### 零、缺失、并列与不适用

- 历史资源分母为 0 时 Yield 未定义；资源缺失、负值或期间不完整时应按明确业务规则标为不可比较，不能除以零、替成 0 或用极大值入图。负分母若业务确有退回 / 冲销场景，须先明确口径，当前能力包不自行解释。
- C3 为 0 且正分母有效时，Yield 可为真实的 0。有效负 C3 对应负 Yield，不应因数值不好看而截为 0；是否纳入可比样本由已说明的业务规则决定。
- 计划投入为 0 可以是真实坐标，不能与缺失值混为一谈。未创建计划记录是否等于 0，由工程侧业务规则决定，不能由模型猜测。
- 排名并列保留并列语义，不挑一个宣称唯一最高。多个点重叠时由渲染器提供聚合数量、明细或悬浮信息；不能抖动后把视觉位置当成真实金额 / Yield。
- 本版本少于 4 个有效入图对象、任一轴值全相同或无法形成有意义分组时，退化成已提供的短表（table），并说明“暂不作四象限判断”。4 点是当前图形组件的展示门槛，不是业务风险阈值；当前协议不支持独立的普通散点图。未来若要配置展示门槛或增加图种，需要同步数据协议、校验和渲染器。
- 未入图对象需要数量及排除原因，具体对象是否可见遵守权限。排除不是正常，也不是异常；不能默默丢弃后报告“全部已检查”。

四象限是回看历史和讨论计划的定位工具，不是 ROI 优化模型。历史整体 Yield 与部门计划投入的组合尤其需要明确范围差异；与历史整体 Yield 对照不代表当前部门的历史回报，不得把整体 Yield 改写为部门 Yield。它不能证明未来回报、投入过多 / 不足或给出自动增减金额。

## 其他可视化的数据准备

| 类型 | 适用问题 | 上游必须保证 |
|---|---|---|
| comparison | 少量时期 / 对象的金额对比 | 单位一致，实际 / 计划属性明确；跨年变化不能命名同比 |
| composition | 预算去向、其他安排原因分布 | 子项互斥，分母明确，合计可核对；超额或负余额不伪装正常构成 |
| ranked_bar | 经销商集中对象 | 排序及并列规则已计算，截断展示交代其余项，比例分母一致 |
| quadrant | 历史 Yield 与本期计划的相对位置 | 坐标、样本、阈值、象限和排除原因齐全 |
| table | 少量需核对对象 / 原因 | 可读标签、统一单位、事实追溯；避免长表挤占主结论 |

模型选择已有 dataset_id，不生成 chart config，也不重算数值。选中的数据集 kind 必须属于 task.allowed_visuals；所需图不允许时，优先使用已经提供且属于允许范围的对应 table，否则用文字说明，不能擅自切换 preset_id 或构造新数据集。渲染器负责统一样式和交互；客户后续扩展新图表类型时，需要同时扩展数据协议、校验与组件，不能仅修改提示词要求输出任意图。

## 六维状态由证据约束

每次 evidence 必须包含全部六个 check_constraints，allowed_statuses 由可信上游生成，reason 解释约束原因。例如：没有 2027 目标不必完全禁止呈现历史趋势事实，但不能声称已证明 2027 投入与目标匹配；没有跨部门明细仍可分析本范围多 Initiative 叠加，但不能声称已排查所有跨部门重复。

可选 required_focus 默认 false；上游对已确定必须醒目呈现的事实（如预算超额）设为 true，并提供相应事实和允许 review 的状态约束。生成结果必须存在关联该维度的 review 正文块，校验器应验证这一点。模型仍然选择标题、图文方式和关联发现的组织，但不能因为“本轮只展示少量重点”而漏掉必显事项。若 required_focus 与 allowed_statuses 冲突，应由接入端拒绝或修正输入，不让模型猜测哪个字段优先。

clear 需要“足够证据 + 已定义检查口径 + 无突出事项”；只有数值没有判断标准通常是 observed；有具体矛盾或值得核对的组合可为 review；关键证据不足为 limited。上游约束是边界，模型可以在允许状态内结合证据判断，不承担权限判断或创造业务阈值。

预算完整性至少区分金额平衡、经销商分配、其他预算安排和原因完整性。零差额不能覆盖原因缺失，也不能把暂存预留当作已经到经销商的投入。

## 提示词能自由改到什么程度

可以直接修改 prompts 下的措辞、分析侧重、图文选择偏好、典型例子、解释详略和排序原则。公共文件与选中方案在每次构造请求时重新读取，避免提示词藏在代码常量里。客户界面只选择已发布的分析方案；维护人员仍可像普通 Markdown 一样编辑提示词。

修改后仍需保持：权限 / 事实边界、schema 字段、已支持的图表类型及六维覆盖。改变这些是协议或业务规则变更，需要同步适配与验证。这类约束确保结果能安全渲染，不限定模型必须写哪六段话。不要把所有经验都升级为“必须输出”的模板规则。

上线前应对同一批正常、需复核、证据不足案例做对照：事实可追溯、无越权、无虚构计算、六维不遗漏、正常场景不凑问题、重点场景可辨认、无图也能成立。文字风格允许变化，不以固定句子是否匹配作为正确性标准。是否开启 Qwen 思考模式或换模型，需要另做同证据质量 / 延迟实测；能力包本身不宣称某个模型已验证通过。
