# Insight 真实 Qwen 效果复核 · 2026-10-11

> 后续 v0.1.4 一致性与时延调整见 [最新实测记录](Insight一致性与时延实测_20261011.md)。本文保留上一轮事实。

结论：工程调用、结构化输出、保存回读和主要边界可以运行；业务分析质量仍未完全达到“事实准确、正常情况不制造风险、引用能逐项核对”的期待。本次已修复两个确定的证据构造缺陷，并增强公共提示词。真实复测证明硬缺陷已纠正，但单靠追加提示词尚不能稳定消除过度复核、文字与图表不匹配等问题。适合人工复核的分析助手，尚不适合无人复核的业务审阅。

## 尚未解决的具体问题

1. **正常检查仍会被包装成风险。** 调整后 healthy.comprehensive 的标题仍为“预算找平且规则检查通过，需关注低Yield高投入及多项叠加对象”；正文仍建议确认重复激励。这与上游已确认规则通过的语义不一致。JSON 中 observed 合法，并不能保证中文没有误报。
2. **局部数字比较和图文关联仍会错。** 调整后 baseline.comprehensive 的 low_yield 摘要把 51,000 相对 47,500 的位置写成“附近或以下”。同一报告还用只含个体明细的 yield-table 承载完整象限分界解释。标题、ID 存在且合法，并不等于文字确由该图支持。
3. **泛化引用仍会通过。** 调整后的工程 baseline 在计划投入排序图正文中讨论 Yield 象限，引用仍是 cohort/allocated；缺少对应历史事实或象限数据的直接绑定。新增可引用事实有帮助，但模型并不总会选择它们。
4. **上下文增加明显。** 四个工程场景平均输入从 12,612.5 升至 17,646.5 tokens，约增加 39.9%；总返回使用量从 57,104 升至 77,301，约增加 35.4%。新增逐对象事实及请求 schema 中的事实 ID 枚举会增加输入，应在全量经销商场景前压缩和测量。
5. **可用性存在波动。** 本轮有连接、协议、读取超时，以及根因未确认的 HTTP 502。后续成功不能反证此前失败。当前错误提示保留原记录是合理的，但不足以诊断原因。

## 建议调整顺序

优先保留本轮确定性的证据修复，继续使用当前模型进行同样样本的对照，不宜据此直接换模型。下一阶段的重点应从“继续加提醒句”转向可验证的语义边界：

1. 给确定性发现增加结构化结论代码、对象及对应证据，例如预算超额、说明缺失、仅相对位置、已确认规则通过。模型负责组织文字；持久化前校验结论与代码、对象、数值和分组一致。发现不一致时拒绝该结果或按明确规则降级，不能静默改成通过。
2. 将 healthy 三方案纳入重复实测验收，特别检查无依据的“优先复核”“重复激励”“配置合理”等判断；图表段落只允许解读该数据集实际包含的字段，跨主题说明使用独立发现并绑定相关证据。
3. 压缩逐对象证据和重复 schema 描述，保留全量计算及可追溯性，再测试接近实际规模的授权队列。不要简单截 TopN 后把子样本结论说成全局结论。
4. 增加脱敏的请求 ID、错误类别和耗时日志；对可重试的连接/服务端错误实施有上限的重试，明确重复请求可能带来的费用。是否扩大自动重试应结合业务等待时限设置。

本轮没有实现上述新的语义协议或自动重试，也未把剩余问题标为已解决。
