# Shell Forecast 后端接口说明

## 1. 基本约定

- 本地服务地址：`http://127.0.0.1:8000`
- API 前缀：`/api/v1`
- 除文件下载接口外，成功响应统一为：

```json
{
  "code": 200,
  "msg": "响应成功",
  "data": {}
}
```

- 失败响应同样使用 `code`、`msg`、`data`。参数校验失败的 HTTP 状态码和 `code` 均为 `422`，具体字段错误位于 `data.errors`。
- PostgreSQL 的 `NUMERIC` 金额和比例以 JSON 字符串返回，例如：`"25000.00"`、`"0.2500"`。前端展示或计算时应按十进制数值处理，避免浮点精度误差。
- Swagger UI：`/docs`；OpenAPI JSON：`/openapi.json`。

## 2. 工作台临时身份与数据范围

当前尚未接入 SSO。所有 `/api/v1/workbench` 接口临时固定为：

| 字段 | 当前值 |
| --- | --- |
| 用户 | 用户A（`user-a`） |
| 部门 | `MKT` |
| 业务线 / Sector | `PCMO` |
| 规划年度 | `2027` |

因此，工作台接口只读取或修改 `2027 + MKT + PCMO` 范围内的 `data.budgets` 与 `data.budgets_distributor` 数据。后续接入 SSO 后，应替换临时身份依赖，不改变 Controller → Service → Repository 的分层。

状态字段约定：`0` 为编辑中，`1` 为已完成。

## 3. 健康与测试接口

`GET /health`

用途：确认后端进程可用。

示例响应：

```json
{

  "data": {
    "status": "ok",
    "service": "Shell Forecast Backend",
    "version": "0.1.0",
    "environment": "development"
  }
}
```

示例响应：

```json
  "msg": "响应成功",
  "data": {

  }
```

用途：验证 JSON 请求体和统一响应体。

```json
{
  "message": "hello"
```

```json

  "code": 200,

  "data": {
    "message": "hello"
  }
```

### 3.4 PostgreSQL 链路测试

`GET /api/v1/test/database-value`

用途：验证 Controller → Service → Repository → DO → PostgreSQL 的连通性，读取 `data.test_table` 的第一条值。

成功示例：

```json
{
  "code": 200,
  "msg": "响应成功",
```

### 3.5 Azure Blob 上传测试

`POST /api/v1/test/blob/upload`

| 位置 | 参数 | 类型 | 必填 | 说明 |

## 4. 我的工作台接口

### 4.1 获取我的 Initiative 列表与汇总

`GET /api/v1/workbench/my-initiatives`

用途：获取当前临时用户负责范围内的 Initiative 列表、负责预算总额和完成进度。汇总始终基于该用户范围的全部预算，不受列表筛选条件影响。

查询参数：

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `initiative_keyword` | string | 否 | Initiative 名称模糊查询，最大 255 字符 |
| `resource_type_keyword` | string | 否 | Resource Type 模糊查询，最大 64 字符 |
| `status` | integer | 否 | `0` 编辑中，`1` 已完成 |

请求示例：

```text
GET /api/v1/workbench/my-initiatives?initiative_keyword=Trade&status=0
```

成功示例：

```json
{
  "code": 200,
  "msg": "响应成功",
  "data": {
    "current_user": {
      "user_id": "user-a",
      "user_name": "用户A",
      "department": "MKT",
      "sector": "PCMO"
    },
    "initiatives": [
      {
        "id": 101,
        "planning_year": 2027,
        "sector": "PCMO",
        "department": "MKT",
        "resource_type": "Trade Support",
        "initiative": "渠道推广",
        "budget": "100000.00",
        "allocate_budget": "80000.00",
        "status": 0
      }
    ],
    "responsible_budget": {
      "planning_year": 2027,
      "initiative_count": 1,
      "total_plan_budget_amount": "100000.00"
    },
    "completion_progress": {
      "total_initiative_count": 1,
      "completed_initiative_count": 0,
      "pending_initiative_count": 1
    }
  }
}
```

### 4.2 获取 Initiative 的经销商分配列表

`GET /api/v1/workbench/initiatives/{budget_id}/distributor-allocations`

用途：查询指定 Initiative 下的经销商预算分配。

路径参数：

| 参数 | 类型 | 说明 |
| --- | --- | --- |
| `budget_id` | integer | `data.budgets.id`，必须属于当前工作台范围 |

成功示例：

```json
{
  "code": 200,
  "msg": "响应成功",
  "data": [
    {
      "id": 501,
      "distributor_code": "D001",
      "allocate_amount": "25000.00",
      "rate": "0.2500",
      "desc": "首轮分配"
    }
  ]
}
```

`rate` 为 `allocate_amount ÷ budget`，由服务端实时计算，不单独保存到数据库。

### 4.3 新增经销商分配

`POST /api/v1/workbench/initiatives/{budget_id}/distributor-allocations`

用途：为指定 Initiative 新增一条经销商预算分配。

路径参数：`budget_id`，规则同 4.2。

请求体：

```json
{
  "distributor_code": "D001",
  "distributor_budget_amount": "25000.00",
  "description": "首轮分配"
}
```

字段规则：

| 字段 | 类型 | 必填 | 规则 |
| --- | --- | --- | --- |
| `distributor_code` | string | 是 | 去首尾空格后不能为空，最多 255 字符 |
| `distributor_budget_amount` | decimal | 是 | 非负，最多 18 位有效数字、2 位小数 |
| `description` | string | 否 | 最多 255 字符；空白会保存为 `null` |

成功响应的 `data` 结构与 4.2 单条记录相同，`msg` 为 `新增成功`。同一 Initiative 下经销商编码重复时，返回 HTTP `409`。

### 4.4 修改经销商分配

`PATCH /api/v1/workbench/initiatives/{budget_id}/distributor-allocations/{allocation_id}`

用途：修改经销商分配金额和/或说明。

路径参数：

| 参数 | 类型 | 说明 |
| --- | --- | --- |
| `budget_id` | integer | Initiative 预算 ID |
| `allocation_id` | integer | `data.budgets_distributor.id`，必须属于该 Initiative |

请求体示例：

```json
{
  "distributor_budget_amount": "30000.00",
  "description": "调整后的分配说明"
}
```

两个字段至少提供一个。成功响应的 `data` 结构与 4.2 单条记录相同，`msg` 为 `修改成功`。不属于当前 Initiative 或当前用户范围时返回 HTTP `404`。

### 4.5 删除经销商分配

`DELETE /api/v1/workbench/initiatives/{budget_id}/distributor-allocations/{allocation_id}`

用途：删除指定 Initiative 下的一条经销商分配。

路径参数规则同 4.4。

成功示例：

```json
{
  "code": 200,
  "msg": "删除成功",
  "data": null
}
```

### 4.6 获取 Initiative 预算汇总

`GET /api/v1/workbench/initiatives/{budget_id}/budget-summary`

用途：返回 Initiative 总预算、当前经销商已分配金额和未解释差额。

计算公式：`unexplained_difference = budget - allocated_amount`。

成功示例：

```json
{
  "code": 200,
  "msg": "响应成功",
  "data": {
    "budget_id": 101,
    "initiative": "渠道推广",
    "budget": "100000.00",
    "allocated_amount": "75000.00",
    "unexplained_difference": "25000.00"
  }
}
```

### 4.7 下载经销商分配导入模板

`GET /api/v1/workbench/distributor-allocation-template`

用途：从 Azure Blob 下载经销商分配 Excel 模板。

响应：成功时直接返回 `.xlsx` 文件流，包含 `Content-Disposition: attachment`，不使用统一 JSON 响应体。

配置要求：在被 Git 忽略的 `backend/config/settings.toml` 当前环境段增加：

```toml
azure_blob_workbench_template_name = "distributor-allocation-template.xlsx"
```

该 Blob 必须存在于 `azure_blob_container_name` 指定的容器中。未配置模板返回 HTTP `503`；配置的 Blob 不存在返回 HTTP `404`；Blob 服务异常返回 HTTP `502`。

### 4.8 Excel 批量导入经销商分配

`POST /api/v1/workbench/initiatives/{budget_id}/distributor-allocations/import`

用途：读取经销商分配 Excel 文件，并将全部有效行作为新增数据写入指定 Initiative。整个文件在一个数据库事务中处理，任一行不合法或存在重复记录时，整份文件都不会写入。

参数：

| 位置 | 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- | --- |
| Path | `budget_id` | integer | 是 | Initiative 预算 ID |
| `multipart/form-data` | `file` | `.xlsx` 文件 | 是 | 最大大小由 `azure_blob_max_upload_bytes` 配置，默认 20 MiB |

支持以下任一组表头：

| 业务字段 | 支持表头 |
| --- | --- |
| 经销商编码 | `distributor_code` 或 `经销商编码` |
| 分配金额 | `allocate_amount`、`distributor_budget_amount` 或 `分配金额` |
| 说明 | `desc`、`description` 或 `说明` |

Excel 文件中的 `rate` 列不是导入字段，服务端会使用总预算重新计算返回值。空行会跳过；经销商编码在同一文件内重复、金额非法或缺少必需表头时返回 HTTP `400`；与数据库现有记录冲突时返回 HTTP `409`。

成功示例：

```json
{
  "code": 200,
  "msg": "全部导入完成",
  "data": {
    "imported_count": 3
  }
}
```
