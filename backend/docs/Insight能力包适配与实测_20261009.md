## “待补充信息”的新口径

有历史 Yield 和计划投入时，正常展示事实与相对位置；有完整年度 Vol/C3 数据时，展示可核对的经营变化。没有未来目标不再将整项判断强制标成缺依据，也不凭历史直接判断未来投入是否合理。

真正缺少关键历史数据时使用“待补充信息”，明确缺哪项、影响哪项分析及补充方向。界面使用中性色，减少正文中的反复提示。未来目标或同口径基线的边界放在报告末尾，超预算等明确问题仍优先显示。报告标题与摘要在前，六维检查始终默认展开。

## 真实 Qwen 测试

调用本地已配置的 `qwen3.8-flash` 真实 API，`enable_thinking=false`，JSON Schema 模式。密钥仅从已忽略的本地配置读取；测试使用合成证据与独立 SQLite，没有访问业务 PostgreSQL。

最终能力包矩阵：**12/12 通过结构、状态、引用及图表校验**；本轮合计 84,992 tokens，单次耗时 20.72–36.12 秒。四种场景分别运行三个方案：

| 场景 | 综合体检 | 四象限 | 结构分析 | 重点核验 |
| --- | --- | --- | --- | --- |
| 常规关注 | 通过 | 通过 | 通过 | 预算平衡、跨年参考、相对定位 |
| 正常 | 通过 | 通过 | 通过 | 有规则可陈述正常，不人为制造缺数据 |
| 历史缺失 | 通过 | 通过 | 通过 | 缺失不补零；仅缺历史的维度提示补充 |
| 超预算 | 通过 | 通过 | 通过 | 三种方案均显式突出超额 55,000 元 |

原始模型结果、有限归一化后的结果、请求 ID、用量、输入证据与提示词哈希保存在 `backend/.cache/insight-live/20261009-release-matrix/`，汇总为 `summary.json`。这是模型实测文件，不是包内人工编写的示例结果。

工程内另通过真实 Controller → Service → Repository 生成三个方案，耗时分别为 33.98、29.34、27.88 秒，合计 44,206 tokens；**25/25 联调检查通过**，覆盖按方案保存及读取、六维完整、权限范围、管理层只读、禁用用户提示词编辑、非法方案拒绝、预算未改动。结果位于 `.cache/insight-integration/results/`。最新三份工程输出经独立复核，未发现数字、象限归属或图文配对的硬错误。

实际端点拒绝 `uniqueItems`；工程只在发送的 Schema 中移除此关键字，本地严格校验保留。请求同时限定实际事实 ID、可用图表、各维度状态；图形块绑定真实数据集标题与事实。集合引用中的完全重复项可稳定去重，并在 `normalizations` 中记录，不改金额、结论、状态或六维对象。没有自动重试、切换模型或静默改用 JSON Object。

早期测试中遇到非法状态、错图和本机代理连接失败。失败未当作成功，也未写成业务分析记录；最终矩阵采用逐个调用。

## 效果边界

独立审阅最终 12 组结果，金额、超额必显、缺失不补零、800 的象限位置及图文配对未发现关键错误。但仍有少量自然语言问题：部分列表的最高值偶被泛化为范围最高、正常性评价偏主观、同一表格重复展示。**校验通过不代表每句业务解释都准确**，当前定位为可查看原始依据、由业务人员复核的辅助分析。

历史资源表没有 Initiative 同口径的历史投入基线；不擅自合计跨部门资源来推算投入回报或跨年增长。旧 Insight 若没有 sectors 授权快照会保守隐藏，原记录保留，可重新生成。
