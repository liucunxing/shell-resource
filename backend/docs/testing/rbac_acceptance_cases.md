# 资源规划工作台 RBAC 验收用例

## 1. 验收基线

本文严格以开发方确认的权限矩阵为准，不采用临时放宽的历史数据权限。

角色：

- Owner：仅本人负责的 Initiative。
- 部门负责人（Lead）：本部门且在本人 Sector 范围内的 Initiative，业务操作只读。
- 管理层（Management）：仅最新同步快照；不可读取未同步工作稿。
- 管理员（Admin）：全部预算配置；不可读取业务分配明细或同步版本。

| 账号 | 角色 | 部门 | Sector |
|---|---|---|---|
| `sf-admin@example.test` | admin | — | — |
| `sf-management@example.test` | management | — | — |
| `sf-mkt-lead@example.test` | lead | MKT | PCMO |
| `sf-owner-a@example.test` | owner | MKT | PCMO |
| `sf-owner-b@example.test` | owner | MKT | PCMO |
| `sf-ice-owner@example.test` | owner | ICE | PCMO |

执行 [rbac_acceptance_seed.sql](rbac_acceptance_seed.sql) 后生成：

| 数据代码 | Initiative | Owner | 当前工作稿 | 同步状态 | 主要用途 |
|---|---|---|---|---|---|
| A_DRAFT | `[RBAC-TEST] A-未配平草稿` | Owner A | 90000 / 100000 | 无版本 | 未配平保存、同步失败 |
| A_DRIFT | `[RBAC-TEST] A-发布后已修改` | Owner A | 80000 分配 + 40000 其他预算 | 版本 1 为 70000 + 50000 | 草稿与管理层快照隔离 |
| B_PUBLISHED | `[RBAC-TEST] B-已发布` | Owner B | 50000 + 30000 | 已同步 | Owner 隔离、MKT 汇总 |
| ICE_PUBLISHED | `[RBAC-TEST] ICE-已发布` | ICE Owner | 45000 + 15000 | 已同步 | 跨部门隔离 |

经销商编码从 `data.distributor_sellin_resource_history` 按编码排序取前 8 个，避免伪造不存在的编码。

## 3. 推荐执行顺序

1. 执行测试种子并记录四个 Budget ID。
2. Admin 验证配置权限和业务数据禁区。
3. Owner A 验证本人项目、未配平草稿和版本冲突。
4. Owner B 验证同部门 Owner 隔离。
5. ICE Owner 验证跨部门隔离。
6. Lead 验证本部门工作稿只读。
7. Management 验证只读最新同步快照。
8. Owner A 再次同步 A_DRIFT，验证管理层最新版本切换和旧版本不可变。
9. 验证 Insight、日志、导出和 Excel 反向权限。
10. 如需恢复环境，执行 [rbac_acceptance_cleanup.sql](rbac_acceptance_cleanup.sql)。

## 4. 前端点击验收手册

本节中的文案均使用当前前端实际菜单和按钮名称。页面显示范围用于验收用户体验，但不能替代后端权限验证；涉及直接访问他人 Budget ID、伪造 revision或非法文件的用例，必须继续按后文接口用例验证。

### 4.1 通用登录与切换账号

1. 首次进入系统时，在“开发环境登录”页的“邮箱”输入框填写测试账号，点击“进入工作台”。
2. 切换账号时，在左下角“当前用户”区域点击“切换开发邮箱”，再输入新账号并点击“进入工作台”。
3. 每次切换后先核对左下角邮箱和角色名称，再开始记录截图。切换前如有 Owner 未保存编辑，先点击“保存草稿”。

### 4.2 Owner A 主链路（INIT-01/02、DRAFT-01～07、PUB-03/05、REF-06、XLS-01～05、INS-01/02/03/09、LOG-01/06）

| 步骤 | 前端如何操作 | 预期页面效果 |
|---|---|---|
| 1 | 登录 `sf-owner-a@example.test`，点击左侧“我的工作台” | “我的 Initiative”显示 **2 项**：`[RBAC-TEST] A-未配平草稿`、`[RBAC-TEST] A-发布后已修改`；不得显示 B 或 ICE 项目。这是 INIT-01 的主验收点。 |
| 2 | 在“搜索 Initiative / 资源类型”中分别搜索 `B-已发布`、`ICE-已发布` | 表格显示“没有匹配的 Initiative”，不得显示项目名、预算或 Owner。之后清空搜索框。直接伪造 Budget ID 的 404 仍用 INIT-02 接口验证。 |
| 2A | 点击左侧“部门总览” | 按权限矩阵，Owner 的汇总数字和下方列表都应只按 Owner A 的两个项目计算，不得把 Owner B 的 B_PUBLISHED 计入预算、分配或项目数。如页面显示整个 MKT 部门汇总，本项判定 Fail。 |
| 3 | 在 A_DRAFT 行点击“查看 / 调整” | 进入项目明细；显示“经销商分配”、“其他预算安排”，预算为 100000，当前合计 90000，页面提示未配平；“同步最新分配”为禁用状态。 |
| 4 | 不修改数据，点击“保存草稿” | 提示“草稿已保存。”，未配平数据仍保留；验证 DRAFT-01。因前端会禁用同步按钮，DRAFT-02 的 422 必须通过接口补测。 |
| 5 | 点击“一键找平”，核对新增/更新的其他预算行；也可点“+ 添加安排”后填写金额和“具体原因” | 差额变为 0，出现“分配与预算平衡，可同步给管理层”，“同步最新分配”变为可点击。 |
| 6 | 点击“保存草稿”，再点击“同步最新分配” | 分别提示“草稿已保存。”和“已同步最新分配，仍可继续修改。”；“最新同步”时间更新，“同步历史（1）”可查看版本 1；验证 DRAFT-03。 |
| 7 | 进入 A_DRIFT，点击“同步历史（1）” | 弹窗显示“第 1 次同步”，版本内经销商分配合计 70000、其他预算 50000；当前页面工作稿仍为 80000 + 40000。 |
| 8 | 关闭弹窗，点击“保存草稿”和“同步最新分配”，再打开“同步历史（2）” | 出现第 1、2 次同步；版本 1 仍为 70000 + 50000，版本 2 为 80000 + 40000；验证 PUB-03/05。 |
| 9 | 在明细页点击“下载模板”；修改后点“导入 Excel”选择文件 | 合法文件显示“Excel 导入预览”，列出导入前/后/变化和导入后差额；点“确认写入”后只更新当前项目工作稿。非法文件在预览中显示错误且“确认写入”禁用；验证 XLS-01～05。 |
| 10 | 返回“我的工作台”点击“我的 Insight”，或在单项行点“Insight” | 右侧 Insight 面板可在“我的全部 Initiative”和 Owner A 的单项之间切换；可展开“编辑分析提示词”、点击“保存提示词”及“生成六点分析/更新分析”；不得出现 Owner B 项目。验证 INS-01/02；INS-03/09 需接口补测。 |
| 11 | 点击左侧“原始数据”，依次查看“分配明细”、“预算明细”、“其他预算明细”和“历史数据”，最后点“导出当前筛选 CSV” | 前三个页签只含 Owner A 的两个项目；历史页签按正式权限预期只含本人项目涉及的经销商和授权字段；导出后提示“已导出当前筛选的数据。”。用表格软件查验 CSV 范围及公式注入转义；验证 LOG-01/06 的可见部分。 |

> DRAFT-04～07、XLS-02～05 中前端能拦截的错误应显示明确校验提示且不得写入；为确认后端安全边界，仍需用接口构造空说明、重复/不存在经销商、过期 revision 等请求。

### 4.3 Owner B 与 ICE Owner 隔离（INIT-03/04、XLS-07、LOG-02）

1. 切换为 `sf-owner-b@example.test`，进入“我的工作台”：只应显示 `[RBAC-TEST] B-已发布`，不得显示 Owner A 或 ICE 项目。
2. 进入 B 项目“查看 / 调整”：可查看本项工作稿、下载/导入 Excel、保存和同步。左侧“原始数据”只应导出 B 项目范围。
3. 切换为 `sf-ice-owner@example.test`，重复上述查看：只应显示 `[RBAC-TEST] ICE-已发布`，不得显示任何 MKT 项目。
4. XLS-07（Owner B 向 Owner A Budget ID 上传）和直接读取他人日志没有正常前端入口，必须用接口验证 404/不泄露。

### 4.6 管理员（INIT-10/11、ADM-01～08、REF-01～05/09、XLS-06、INS-08、LOG-05/06）

| 步骤 | 前端如何操作 | 预期页面效果 |
|---|---|---|
| 1 | 登录 `sf-admin@example.test`，点击“管理后台”→“预算与归属” | “预算与 Owner 映射”显示四个测试 Initiative 的名称、Sector、资源类型、部门/Owner 和预算；不展示经销商分配、其他预算或同步历史。 |
| 2 | 在任一行点“调整预算”，输入新金额并保存；再点“分配 Owner”选择同部门 Owner 并保存 | 出现保存成功提示，列表中预算/Owner 更新；页面明确提示不自动重分配，原同步快照不应立即变化。测试后建议改回种子值。 |
| 3 | 点“导出配置”。已有行可修改浅蓝色的预算或 Owner；需要新增时，在表尾增加一行，将 Initiative 编号、修订号、状态留空，并填写名称、Sector、资源类型、部门、Owner、预算。再点“导入 Excel” | 先出现“管理员配置导入预览”，分别标记“新增”和“修改”，并显示导入前后总预算；无错误时按钮显示“确认导入 N 项”。确认后新增与修改在同一事务整批写入，任一行失败则全部不写入。未知但非空的编号、过期 revision、非法 Owner、资源类型与部门不匹配或重复业务键均应阻止导入。 |
| 4 | 点“预算原因配置”，点“+ 添加原因”或已有原因的“改名”/“停用” | 原因列表和“启用/停用”状态更新；被现有预算行使用的原因不得被删除。 |
| 5 | 点“参考数据批次”→“导入历史 JSON”，选择合法年度文件 | 页面显示服务端校验/导入结果，批次号、导入时间和记录数随成功导入更新；重复编码、非法数值和过期 revision 应报错且原批次不变。实施差异见第 7 节注意事项。 |
| 6 | 点“分析指南”，修改“指南内容”并点“保存为新指南版本” | 版本号递增，显示配置已保存；旧 Insight 应标记待更新。管理员不得出现业务 Insight 生成或提示词编辑入口。 |
| 7 | 点“变更记录” | 只应显示预算/归属、原因字典、参考数据导入、分析指南等管理日志；不应将 Owner 的分配明细作为管理员可见业务数据。 |
| 8 | 点左侧“原始数据” | 默认只有“预算配置”和“历史数据”页签，不得出现“分配明细”或“其他预算明细”；点“导出当前筛选 CSV”后，文件仅包含当前获准的配置/参考数据。 |

ADM-01“新增预算”通过管理员配置 Excel 的空编号行完成；页面没有单独的新增按钮。INIT-11、ADM-03～05/08、REF-04/05、XLS-06、INS-08 属于越权或并发反向用例，仍需通过接口执行并记录 HTTP 状态码。

### 4.7 前端无法独立覆盖的用例

| 类型 | 用例 ID | 原因与验收方式 |
|---|---|---|
| 直接越权读写 | INIT-02/07/09/11、ADM-08、REF-05、XLS-06/07、INS-03/05/07/08 | 正常前端不提供入口；使用对应账号直接调用 API，核对 403 或 404。 |
| 并发版本冲突 | DRAFT-05、ADM-03、REF-04、INS-09 | 页面通常只使用最新 revision；保留旧 revision 后构造请求，预期 409，再刷新页面确认新数据未被覆盖。 |
| 非法业务数据 | DRAFT-04/06/07、ADM-04/05、REF-02/03、XLS-02～05 | 前端可先验证错误提示和禁用确认；还需绕过前端直接调用 API，确认整项/整批不写入。 |
| 版本列表 | PUB-05/06 | Owner/Lead 可在明细页点“同步历史”；Management 和 Admin 的正常页面不提供该入口，需分别用接口验证允许和 403。 |
| 日志精确边界 | LOG-01～05 | 页面可见范围先做人工核对；同时直接查询日志 API，确认不仅是前端隐藏。 |
| CSV 公式注入 | LOG-06 | 用带 `=`、`+`、`-`、`@ 开头文本的可见数据导出 CSV，用文本编辑器检查原文，不能只依赖 Excel 的渲染结果。 |

## 11. 验收记录模板

每个用例至少记录：

|---|---|
| 用例 ID | 如 `PUB-01` |
| 执行账号 | 完整测试邮箱 |

| 请求 | 方法、URL、关键请求体；不记录密钥 |

| 实际数据范围 | 返回项目、经销商、版本数量 |
