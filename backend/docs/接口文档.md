# 资源投资工作台 V20 接口文档

此文件是前后端联调的唯一接口文档，覆盖当前新增和调整的工作台接口及保留的基础接口。默认业务前缀为 `/api/v1/workbench`；下文除基础接口外均省略该前缀。实际字段以本文件和 `/openapi.json` 为准，前端不要直连数据库。

## 管理员项目新增、完整编辑与删除

新增沿用 `POST /admin/budgets`，请求 `{planning_year, items: [{name, sector, resourceType, department, ownerId, budget}]}`。

`PUT /admin/budgets/{budget_id}` 支持修改全部六个字段，并要求 `expected_revision`。复用新增的长度、金额、资源类型、部门内 Owner 及业务键唯一性校验；邮箱匹配忽略大小写，资源类型保存标准枚举值。编辑保留分配金额，更新分配行冗余元数据，并增加修订号、标记待同步；历史快照不改写。

`DELETE /admin/budgets/{budget_id}` 要求 JSON 请求体 `{expected_revision}`。确认后删除目标预算及经销商分配、其他预算和同步记录，后台保存完整删除前快照及 ADMIN_DELETE 日志，原审计记录保留。接口不提供页面撤销。

两者均仅管理员可调用，事务失败回滚。成功数据分别为 `{updated_id}`、`{deleted_id}`；不存在返回 404，修订冲突或重复配置返回 409，业务校验失败返回 422。详细操作见 [管理员配置操作](../../docs/ADMIN_BUDGET_CRUD.md)。

## 1. 通用契约

请求为 JSON 时使用 `Content-Type: application/json`。所有工作台接口都要求 `X-User-Email: owner@example.com`；邮箱去首尾空格并转小写，逐请求查询启用的权限记录。缺邮箱 401，未知/停用邮箱或无效角色配置 403。开发身份仅适用于非 production 环境；production 一律返回 401，等待可信登录接入。

| 角色 | 可读范围 | 可写范围 |
|---|---|---|
| owner | 本人拥有的 Initiative | 本人草稿、提交 |
| lead | 本部门工作稿 | 本人担任 Owner 的项目；不能代其他 Owner 改草稿 |
| management | 权限范围内每项最新同步快照、同步历史 | 无 |
| admin | 预算元数据、Owner 候选、配置和管理日志 | 预算/Owner、原因字典、指引、参考批次 |

成功均为 HTTP 200，`code` 为 **200，不是 0**：

```json
{"code":200,"msg":"响应成功","data":{}}
```

失败 HTTP 状态与 `code` 一致：

```json
{"code":409,"msg":"草稿已被其他用户修改，请刷新后重试","data":null}
```

| 状态 | 含义 / 前端处理 |
|---|---|
| 400 | 旧 Excel 文件、表头、行内容不合法 |
| 401 | 缺少身份或当前身份来源不被允许 |
| 403 | 角色或范围不允许操作 |
| 404 | 对象不存在或不在授权范围；不据此探测其他 Owner 数据 |
| 409 | 修订号冲突、重复对象；刷新并重新预览，禁止覆盖重试 |
| 413 | 文件超出上传大小上限 |
| 422 | 参数校验或业务校验失败，例如同步不平衡、原因停用 |
| 502 | Blob 远端调用失败 |
| 503 | 数据库不可用、AI/Blob 尚未配置 |
| 500 | 未分类服务端错误 |

Pydantic 参数校验的 `data.errors` 是错误数组，包含 `loc/type/msg/input` 等信息；业务校验一般 `data:null`。金额非负且最多两位小数，服务端使用 Decimal 计算。新版工作台金额投影为 JSON number；旧 DTO/VO Decimal 响应可能为字符串，前端应显式转数值。日期为 ISO 8601 字符串。预算 ID 路径为整数，新版投影中 ID 为字符串。

### 管理员模拟用户视角（只读）

在现有工作台 GET 请求中附加 `X-Preview-User-Email: target@example.com` 即可按目标用户权限读取；无需新建登录会话或迁移数据库。原身份凭证保持不变：旧入口仍使用管理员的 `X-User-Email`，Portal 入口仍使用管理员 Cookie 和 `X-Portal-Instance`，Portal 业务前缀为 `/portal-embed/api/v1/workbench`。

后端逐请求验证真实操作者仍是启用的管理员，然后读取目标用户当前有效权限。目标用户的角色、部门、业务线、项目归属及同步快照规则沿用普通登录逻辑。模拟模式下，`GET /workspace` 的 `identity` 是目标用户，并增加：

```json
{"preview":{"readOnly":true,"actorEmail":"admin@example.com","actorLabel":"管理员"}}
```

未模拟时 `identity.preview` 为 `null`。移除预览请求头并重新加载 `/workspace` 即返回管理员视角。前端只在当前页面内存中保存目标邮箱，不改写实际登录身份；切换前清空旧工作区、分析结果和问数窗口。

带模拟请求头的业务写请求一律返回 403，包括草稿保存、同步、导入、预算和人员配置。普通用户不能使用该请求头。无效/停用目标不能进入模拟。管理员自身退出登录不受业务只读限制。

操作与验证范围见 [管理员模拟用户视角](../../docs/ADMIN_USER_PREVIEW.md)。

## 3. 工作台、草稿、同步

### GET `/workspace?planning_year=2027`

所有已授权角色可调用。`planning_year` 为必填整数。无可见预算返回空数组，不注入示例数据。返回 `data`：

```json
{
  "identity":{"key":"owner@example.com","email":"owner@example.com","role":"owner","department":"MKT","ownerId":"owner@example.com","label":"Owner"},
  "state":{
    "schemaVersion":2,"scenario":"api","initiatives":[],
    "departments":{
      "MKT":{"status":"collecting","versions":[],"activeVersionId":null,"comments":[]},
      "ICE":{"status":"collecting","versions":[],"activeVersionId":null,"comments":[]},
      "CAPEX":{"status":"collecting","versions":[],"activeVersionId":null,"comments":[]}
    },
    "reference":{},"guide":{"version":0,"text":""},
    "budgetReasons":[{"id":"reserve","label":"新增经销商预留","enabled":true}],
    "budgetReasonVersion":0,"publications":{},"audit":[],"final":null,"configRevision":0
  },
  "data":{"metadata":{"planningYear":2027},"initiatives":[],"allocations":[],"dealers":[]},
  "users":[]
}
```

`state.initiatives` 与 `data.initiatives` 是同一范围的页面投影。Owner/负责人获取当前工作稿；管理层获取最新同步快照；管理员只获取预算元数据，不下发分配明细。`publications` 按预算 ID 分组；Owner/负责人包含各项历史，管理层工作台仅含各项最新版本，更多历史使用 publications 接口。`users` 仅管理员返回，元素为 `{email,label,role,department}`；人员配置接口另返回 `sector`。Initiative 与人员权限均有各自的 Sector 概念。

`data.dealers` 与 `GET /distributors` 均来自 `data.distributor_sellin_resource_history`，不再查询 Databricks。目录元素包含 `id,name,sector,sd,rsm,status`。2026-11-13 确认源状态 `1 = active`、`0 = closed`，兼容数字及文本 1/0，接口统一英文状态。`data.dealers` 保留授权范围内全部历史记录；`GET /distributors` 仅返回 active。Owner 与 Lead 按 `user_permissions.sector` 过滤，Admin 与 Management 可读取全部业务线；目录不扩大历史明细权限。新增分配还须匹配 Initiative 的业务线，否则返回 422；已存的 closed 分配可保留。

`history`提供年度Vol/C3、完整历史投资总额及按授权可见的费用明细。`btl_2025 / btl_2026`映射为SP&A。源Vol为L、C3为USD、历史费用当前为USD；API的Vol/C3保留原值，历史费用除以配置汇率归一为USD，页面除1000显示KL、千美元、千美元。Yield由C3美元÷同期间完整费用美元重算，仅两者均>0且期间可比时有效；历史费用按配置汇率除算至美元、不带x/倍、负值显示“—”，不能解释为未来回报或ROI。YoY按(2025−2024)/2024重算并乘100，基期≤0为无基期；不直接采用源Yield/YoY。受限费用明细不下发，公共完整总额独立返回，不能以部分授权明细求和冒充总额。2026Actual/费用业务截止月未知时不算YTD Yield。Phasing分母为同期间经销商target，当前源未提供，保持缺失；PPP误加占位已取消。

`state.audit` 是页面日志投影；管理层不接收未同步草稿日志，管理员只接收管理配置/预算元数据日志。`departments/final` 为既有页面兼容结构，不表示审批已实现。

2026-11-14 经销商标识：历史和目录逐条返回，不按编码去重；`id` 是业务线、编码、SD、RSM 的稳定记录标识，新增 `code` 返回原始编码。分配 DTO 仍使用 `dealerId`，现在需传所选记录的 `id`，不能用显示编码替代。草稿及快照行另返回 `dealerCode/sd/rsm`。旧分配无归属时保留原来的编码标识，不自动迁移到任意一条组织记录。

### Initiative 投影

GET/PUT draft 返回以下对象；workspace 的 initiatives 元素使用相同结构：

```json
{
  "id":"1","name":"渠道增长","resourceType":"MRD","sector":"B2C","department":"MKT",
  "ownerId":"owner@example.com","budget":100,
  "rows":[{"dealerId":"D001","amount":80,"note":"渠道投入"}],
  "otherBudgets":[{"id":"1","reasonId":"reserve","amount":20,"note":"预留新增经销商"}],
  "revision":1,"publishedRevision":null,"publishedAt":null,
  "reserve":20,"nonDealer":0,"status":"draft","savedAt":"2026-09-23T01:00:00Z"
}
```

`reserve/nonDealer` 是其他预算兼容汇总，不能与 `otherBudgets` 重复计入金额。`revision` 是唯一并发控制版本；`publishedRevision` 是最近同步的草稿版本。`status` 仅表示工作稿状态，管理层的数据来源始终是快照。

### GET `/initiatives/{budget_id}/draft`

Owner 读本人，负责人读本部门范围；管理层和管理员 403。无请求体。成功返回 Initiative。范围外 404。

### PUT `/initiatives/{budget_id}/draft`

仅该项 Owner（角色可为 owner 或 lead，且部门须匹配）。请求为整项替换，**不是增量追加**；传空列表将清空对应集合。前端导出、修改、差异预览并确认 Excel 后也使用此接口：

```json
{
  "expected_revision":0,
  "rows":[{"dealerId":"D001","amount":80,"note":"渠道投入"}],
  "otherBudgets":[{"reasonId":"reserve","amount":20,"note":"预留新增经销商"}]
}
```

`expected_revision` 必填非负；两个列表默认空。`dealerId` 必填且不重复，必须来自本年度经销商目录或该预算已有行；`note` 最长 500。其他预算 `reasonId` 必填，`id` 可为已保存整数、新增临时字符串或省略。停用原因仅允许原有行原样保留或删除，不可新增/修改。整项检查后在一个事务中写入；任一行失败不部分保存。

不要求平衡，非零其他预算也可暂缺说明。成功修订号递增、标记草稿并返回保存后的 Initiative；前端必须采用新 revision。冲突 409 后重新读取草稿及预览，不自动用新版本覆盖。

### POST `/initiatives/{budget_id}/publish`

仅该项 Owner（角色可为 owner 或 lead，且部门须匹配），请求 `{"expected_revision":1,"note":"本轮同步说明"}`，note 可省略，最长 2000。先保存草稿，再用保存响应中的 revision 同步。此操作不会隐式保存前端未提交内容。

经销商分配 + 其他预算必须精确等于预算，且每条非零其他预算必须有说明；否则 422。校验成功追加不可变快照，成功 `data`：

```json
{
  "id":"1","initiativeId":"1","department":"MKT","number":1,
  "createdAt":"2026-09-23T01:00:00Z","publishedAt":"2026-09-23T01:00:00Z",
  "publishedRevision":1,"initiative":{},"reference":{},"guideVersion":1,"note":"本轮同步说明"
}
```

`initiative` 是完整的同步时 Initiative，状态 completed；`reference` 记录依据批次元数据。快照不会随后续草稿、指引或批次修改而改写。再次同步会新增版本。若先保存成功、后同步失败，保存仍有效，前端保留新 revision 并显示同步失败。

### GET `/initiatives/{budget_id}/publications`

Owner/负责人/管理层按当前权限查询，管理员 403。返回上述快照对象的数组，无历史为 `[]`。管理层不能因此读取未同步草稿。

## 4. 管理配置

以下接口仅 admin，批量请求在单一事务内完成。Owner 必须启用且部门匹配；Initiative 与用户均记录业务线，但人员业务线由管理员配置。前端修改成功后重新加载 workspace 获取 revision 和配置。

### 人员与权限 `/admin/users`

仅管理员可调用；非管理员返回 403。`GET /admin/users` 查询包含已停用人员的完整列表。可选参数 `email`、`name` 分别对邮箱和姓名做不区分大小写的字面量模糊匹配，两者同时填写时取交集；`role`、`sector` 精确过滤；`department` 按数组成员精确过滤；`sector` 仅允许 `PCMO`、`CRTO`、`B2B`、`OEM`；`limit` 默认 20、最大 100，`offset` 默认 0。返回：

```json
{"items":[{"id":1,"email":"owner@example.com","display_name":"示例执行人","role":"owner","department":["MKT","ICE"],"sector":["PCMO"],"enabled":true,"has_initiatives":true}],"total":1,"limit":20,"offset":0}
```

`has_initiatives` 表示 `data.budgets.owner_email` 在任意年度存在该邮箱（忽略大小写及首尾空格）。此类人员可调整部门集合，其余字段保持原值；不能移除仍有预算事项的部门，删除仍返回 409。服务端在写入前再次检查。

`POST /admin/users` 新增、`PUT /admin/users/{user_id}` 修改完整人员信息，请求均为：

```json
{"email":"owner@example.com","display_name":"示例执行人","role":"owner","department":["MKT","ICE"],"sector":["PCMO"],"enabled":true}
```

邮箱自动去首尾空格并转小写，不能为空且格式须合法，全表不允许重复（包括停用人员，冲突返回 409）；姓名不能为空。角色只能是 `owner/lead/management/admin`；用户 `department` 为字符串数组（数据库 `varchar(32)[]`）；兼容旧单字符串输入并统一返回数组。Owner 和 Lead 至少选择一个部门；Management 和 Admin 使用空数组。部门去首尾空格并转大写，拒绝空元素及重复值。用户业务线适用于全部所选部门；Owner 业务线必须在每个部门均被启用负责人覆盖。`sector` 仅允许 `PCMO`、`CRTO`、`B2B`、`OEM`：Owner 恰好一条，Lead 一至四条，Management 和 Admin 必须为空。`DELETE /admin/users/{user_id}` 删除无 Initiative 关联的人员，返回 `{"deleted_id":1}`。修改和删除都按用户 ID 定位；不存在返回 404，有 Initiative 关联时仅允许调整部门且必须保留仍有项目的部门，其他修改或删除返回 409。新增、修改、删除记录管理员操作日志。

### POST `/admin/budgets`

```json
{"planning_year":2027,"items":[{"name":"渠道增长","resourceType":"MRD","sector":"B2C","department":"MKT","budget":100,"ownerId":"owner@example.com"}]}
```

年度 2020–2100，items 至少一项，name 最长 255，部门最长 32，新增/编辑 Sector 仅允许 PCMO、CRTO、B2B、OEM；资源类型为 MRD、SP&A、ICE Rebate 或 Capex，与项目部门独立配置。预算非负两位小数。重复业务对象 409，无效 Owner/资源组合 422。返回 `{"created_count":1}`。

### PUT `/admin/budgets`

```json
{"items":[{"id":1,"expected_revision":1,"budget":120,"ownerId":"owner@example.com"}]}
```

每项 id 为正整数且不重复；预算 revision 必须匹配。任意冲突整批 409，不存在或无效 Owner 422。返回 `{"updated_count":1}`，完全无变化的项不增加 revision，updated_count 只统计实际变化。预算/Owner 变更后需重新保存/同步；已存在的历史快照仍保留。

### POST `/admin/budgets/import`

```json
{
  "planning_year": 2027,
  "updates": [
    {"id": 1, "expected_revision": 1, "budget": 120, "ownerId": "owner@example.com"}
  ],
  "creates": [
    {"name": "新品推广", "resourceType": "MRD", "sector": "B2C", "department": "MKT", "budget": 80, "ownerId": "owner@example.com"}
  ]
}
```

用于管理员 Excel 导入。`updates` 和 `creates` 至少有一项，总计不超过 5000 项；更新对象必须属于 `planning_year`。服务端先校验全部修订号、业务唯一键、资源类型有效性以及 Owner 所属部门；资源类型与部门独立配置，再在一个事务中写入，任一项失败则全部回滚。返回 `{"updated_count":1,"created_count":1}`。

### PUT `/admin/config`

```json
{
  "expected_revision":0,
  "budgetReasons":[
    {"id":"reserve","label":"新增经销商预留","enabled":true},
    {"id":"unallocated","label":"无法分配到经销商","enabled":true},
    {"id":"other","label":"其他支出","enabled":true}
  ],
  "guide":{"text":"填写本轮预算分配指引"}
}
```

`expected_revision` 对应 workspace.state.configRevision。budgetReasons 和 guide 可各自省略；原因列表 1–30 项，id 以小写字母起始，仅含小写字母、数字、下划线或连字符，最长 64；label 非空最长 80；enabled 必须布尔值。仍被预算行使用的原因不能删除，可停用。guide.text 必须字符串；version 由后端递增，客户端提交值不会决定版本。

返回 `{revision,budgetReasons,budgetReasonVersion,guide,reference}`。revision 冲突 409，非法字典或删除使用中原因 422。

## 8. 最小联调示例

下列为开发邮箱和合成数据示例；必须先有对应权限/预算/经销商，不是初始化脚本：

```powershell
$base = 'http://127.0.0.1:8000/api/v1/workbench'
$headers = @{ 'X-User-Email' = 'owner@example.com' }
$workspace = Invoke-RestMethod "$base/workspace?planning_year=2027" -Headers $headers
$draft = Invoke-RestMethod "$base/initiatives/1/draft" -Headers $headers
$body = @{
    expected_revision = $draft.data.revision
    rows = @(@{ dealerId='D001'; amount=80; note='渠道投入' })
    otherBudgets = @(@{ reasonId='reserve'; amount=20; note='新增预留' })
} | ConvertTo-Json -Depth 8
$saved = Invoke-RestMethod "$base/initiatives/1/draft" -Method Put -Headers $headers -ContentType 'application/json; charset=utf-8' -Body ([Text.Encoding]::UTF8.GetBytes($body))
$publish = @{ expected_revision=$saved.data.revision; note='本轮同步' } | ConvertTo-Json
Invoke-RestMethod "$base/initiatives/1/publish" -Method Post -Headers $headers -ContentType 'application/json; charset=utf-8' -Body ([Text.Encoding]::UTF8.GetBytes($publish))
```

验收需覆盖同部门两个 Owner 隔离、负责人可维护本人担任 Owner 的项目、其他项目只读、草稿不平衡可保存/不可同步、同步后修改不影响管理层、过期 Excel 无部分写入。本地回归、隔离 PostgreSQL 验证与真实身份/UAT 分别验收。


### 部门负责人兼任 Initiative Owner

### 部门提交、撤回与管理员全版本驳回

`GET /planning-versions/{id}/department?sector=PCMO&department=MKT` 返回
`{version,sector,department,items,total,submitted,confirmed,canConfirm,canWithdraw}`。

`POST /planning-versions/{id}/department/{action}` 仅支持 `confirm`、`withdraw`，仅对应范围部门负责人可操作；请求 `{sector,department,expected_revision,reason}`。

- confirm：版本已发布、开放且未截止，整个部门启用项目均有有效 Owner 提交后才可提交管理层，不受页面筛选影响。提交后锁定 Owner。
- withdraw：同样要求版本开放且未截止，reason 必填；撤回整个部门提交并直接解除该部门所有 Owner 锁，原提交快照及已提交状态保留。之后保存修改才标记待重新提交。该部门分配退出管理层视图。
- 已关闭／截止的版本拒绝部门提交及撤回。原 return 操作取消，单 Owner／单项目参数拒绝。
- 管理员不得代替部门确认或撤回，使用专用全版本驳回接口。

`POST /planning-versions/{id}/release` 仅管理员，模拟视角拒绝；请求 `{expected_revision,deadline,reason}`。deadline 必填、有时区且严格晚于服务端当前时间；服务端在取得版本锁后再次校验。此操作作用于整个版本，不受部门筛选影响：撤销全部部门确认、解除所有 Owner 锁、设置新截止时间并重新开放，保留 Owner 原始提交、未提交草稿和所有历史快照，不把未提交／已修改方案标记为提交。旧流程孤立的 Owner 锁不再阻断无部门确认的项目。

管理员 `PATCH ... {open:false}` 关闭已发布版本时要求全部启用项目都已有有效部门提交；缺交返回409并列出部门。到期自动停止写入而不更改open，不等于管理员关闭。开启其他版本不自动关闭旧版。撤回发布仍是配置操作，不标记业务最终齐交。

所有操作沿用 expected_revision 乐观校验与版本行锁，状态及审计同事务；冲突返回409。管理员驳回的原因记录于 VERSION_RELEASE 审计。

最高管理层可见已配置预算，但只有部门已确认分配进入工作台、快照及下钻。未确认项目 `allocationVisible=false`，`rows/otherBudgets=[]`，`reserve/nonDealer=null`；不能解释为零分配。部门视图仅显示 Owner 已提交快照；本人工作台显示本人草稿。
