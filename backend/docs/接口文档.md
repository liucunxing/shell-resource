# 资源投资工作台 V1.4 接口文档

此文件是前后端联调的唯一接口文档，覆盖当前新增和调整的工作台接口及保留的基础接口。默认业务前缀为 `/api/v1/workbench`；下文除基础接口外均省略该前缀。实际字段以本文件和 `/openapi.json` 为准，前端不要直连数据库。

## 1. 通用契约

请求为 JSON 时使用 `Content-Type: application/json`。所有工作台接口都要求 `X-User-Email: owner@example.com`；邮箱去首尾空格并转小写，逐请求查询启用的权限记录。缺邮箱 401，未知/停用邮箱或无效角色配置 403。开发身份仅适用于非 production 环境；production 一律返回 401，等待可信登录接入。

| 角色 | 可读范围 | 可写范围 |
|---|---|---|
| owner | 本人拥有且符合所属部门及可选 Sector 的 Initiative | 本人草稿、同步、对应 Insight |
| lead | 本部门及可选 Sector 工作稿 | 本部门 Insight；不能代 Owner 改草稿 |
| management | 权限范围内每项最新同步快照、同步历史 | 无；Insight 仅同步数据预览 |
| admin | 预算元数据、Owner 候选、配置和管理日志 | 预算/Owner、原因字典、指引、参考批次 |

成功均为 HTTP 200，`code` 为 **200，不是 0**：

```json
{"code":200,"msg":"响应成功","data":{}}
```

失败 HTTP 状态与 `code` 一致：

```json
{"code":409,"msg":"草稿已被其他用户修改，请刷新后重试","data":null}
```

| 状态 | 含义 / 前端处理 |
|---|---|
| 400 | 旧 Excel 文件、表头、行内容不合法 |
| 401 | 缺少身份或当前身份来源不被允许 |
| 403 | 角色或范围不允许操作 |
| 404 | 对象不存在或不在授权范围；不据此探测其他 Owner 数据 |
| 409 | 修订号/提示词版本冲突、重复对象；刷新并重新预览，禁止覆盖重试 |
| 413 | 文件超出上传大小上限 |
| 422 | 参数校验或业务校验失败，例如同步不平衡、原因停用 |
| 502 | Blob/百炼远端调用失败；Insight 旧结果保留 |
| 503 | 数据库不可用、AI/Blob 尚未配置 |
| 500 | 未分类服务端错误 |

Pydantic 参数校验的 `data.errors` 是错误数组，包含 `loc/type/msg/input` 等信息；业务校验一般 `data:null`。金额非负且最多两位小数，服务端使用 Decimal 计算。新版工作台金额投影为 JSON number；旧 DTO/VO Decimal 响应可能为字符串，前端应显式转数值。日期为 ISO 8601 字符串。预算 ID 路径为整数，新版投影中 ID 为字符串。

## 3. 工作台、草稿、同步

### GET `/workspace?planning_year=2027`

所有已授权角色可调用。`planning_year` 为必填整数。无可见预算返回空数组，不注入示例数据。返回 `data`：

```json
{
  "identity":{"key":"owner@example.com","email":"owner@example.com","role":"owner","department":"MKT","ownerId":"owner@example.com","label":"Owner"},
  "state":{
    "schemaVersion":2,"scenario":"api","initiatives":[],
    "departments":{
      "MKT":{"status":"collecting","versions":[],"activeVersionId":null,"comments":[]},
      "ICE":{"status":"collecting","versions":[],"activeVersionId":null,"comments":[]},
      "CAPEX":{"status":"collecting","versions":[],"activeVersionId":null,"comments":[]}
    },
    "reference":{},"guide":{"version":0,"text":""},
    "insights":{},"analysisPrompts":{},
    "budgetReasons":[{"id":"reserve","label":"新增经销商预留","enabled":true}],
    "budgetReasonVersion":0,"publications":{},"audit":[],"final":null,"configRevision":0
  },
  "data":{"metadata":{"planningYear":2027},"initiatives":[],"allocations":[],"dealers":[]},
  "users":[]
}
```

`state.initiatives` 与 `data.initiatives` 是同一范围的页面投影。Owner/负责人获取当前工作稿；管理层获取最新同步快照；管理员只获取预算元数据，不下发分配明细。`publications` 按预算 ID 分组；Owner/负责人包含各项历史，管理层工作台仅含各项最新版本，更多历史使用 publications 接口。`users` 仅管理员返回，元素为 `{email,label,role,department,sector}`。

`data.dealers` 可包含已登记经销商的 `id/name` 目录以供添加；目录本身不授予历史明细。历史字段仅对当前可见分配对象下发，资源明细按部门限制。`history` 可包含 `vol2024,c32024,vol2025,c32025,vol2026Ytd,c32026Ytd,yield2025,resources2025`；缺失数据为 null 或无该字段，不能当零。Yield 由后端以 2025 C3 / 四类资源合计计算，缺来源或分母不大于零时为 null。

`state.audit` 是页面日志投影；管理层不接收未同步草稿日志，管理员只接收管理配置/预算元数据日志。`departments/final` 为既有页面兼容结构，不表示审批已实现。Insight 用独立接口读取。

### Initiative 投影

GET/PUT draft 返回以下对象；workspace 的 initiatives 元素使用相同结构：

```json
{
  "id":"1","name":"渠道增长","resourceType":"MRD","sector":"B2C","department":"MKT",
  "ownerId":"owner@example.com","budget":100,
  "rows":[{"dealerId":"D001","amount":80,"note":"渠道投入"}],
  "otherBudgets":[{"id":"1","reasonId":"reserve","amount":20,"note":"预留新增经销商"}],
  "revision":1,"publishedRevision":null,"publishedAt":null,
  "reserve":20,"nonDealer":0,"status":"draft","savedAt":"2026-09-23T01:00:00Z"
}
```

`reserve/nonDealer` 是其他预算兼容汇总，不能与 `otherBudgets` 重复计入金额。`revision` 是唯一并发控制版本；`publishedRevision` 是最近同步的草稿版本。`status` 仅表示工作稿状态，管理层的数据来源始终是快照。

### GET `/initiatives/{budget_id}/draft`

Owner 读本人，负责人读本部门范围；管理层和管理员 403。无请求体。成功返回 Initiative。范围外 404。

### PUT `/initiatives/{budget_id}/draft`

仅 Owner。请求为整项替换，**不是增量追加**；传空列表将清空对应集合。前端导出、修改、差异预览并确认 Excel 后也使用此接口：

```json
{
  "expected_revision":0,
  "rows":[{"dealerId":"D001","amount":80,"note":"渠道投入"}],
  "otherBudgets":[{"reasonId":"reserve","amount":20,"note":"预留新增经销商"}]
}
```

`expected_revision` 必填非负；两个列表默认空。`dealerId` 必填且不重复，必须来自本年度经销商目录或该预算已有行；`note` 最长 500。其他预算 `reasonId` 必填，`id` 可为已保存整数、新增临时字符串或省略。停用原因仅允许原有行原样保留或删除，不可新增/修改。整项检查后在一个事务中写入；任一行失败不部分保存。

不要求平衡，非零其他预算也可暂缺说明。成功修订号递增、标记草稿并返回保存后的 Initiative；前端必须采用新 revision。冲突 409 后重新读取草稿及预览，不自动用新版本覆盖。

### POST `/initiatives/{budget_id}/publish`

仅 Owner，请求 `{"expected_revision":1,"note":"本轮同步说明"}`，note 可省略，最长 2000。先保存草稿，再用保存响应中的 revision 同步。此操作不会隐式保存前端未提交内容。

经销商分配 + 其他预算必须精确等于预算，且每条非零其他预算必须有说明；否则 422。校验成功追加不可变快照，成功 `data`：

```json
{
  "id":"1","initiativeId":"1","department":"MKT","number":1,
  "createdAt":"2026-09-23T01:00:00Z","publishedAt":"2026-09-23T01:00:00Z",
  "publishedRevision":1,"initiative":{},"reference":{},"guideVersion":1,"note":"本轮同步说明"
}
```

`initiative` 是完整的同步时 Initiative，状态 completed；`reference` 记录依据批次元数据。快照不会随后续草稿、指引或批次修改而改写。再次同步会新增版本。若先保存成功、后同步失败，保存仍有效，前端保留新 revision 并显示同步失败。

### GET `/initiatives/{budget_id}/publications`

Owner/负责人/管理层按当前权限查询，管理员 403。返回上述快照对象的数组，无历史为 `[]`。管理层不能因此读取未同步草稿。

## 4. 管理配置

以下接口仅 admin，批量请求在单一事务内完成。Owner 必须启用且部门/Sector 匹配。前端修改成功后重新加载 workspace 获取 revision 和配置。

### POST `/admin/budgets`

```json
{"planning_year":2027,"items":[{"name":"渠道增长","resourceType":"MRD","sector":"B2C","department":"MKT","budget":100,"ownerId":"owner@example.com"}]}
```

年度 2020–2100，items 至少一项，name 最长 255，部门和 Sector 最长 32；资源类型必须对应部门：MKT→MRD/SP&A，ICE→ICE Rebate，CAPEX→Capex。预算非负两位小数。重复业务对象 409，无效 Owner/资源组合 422。返回 `{"created_count":1}`。

### PUT `/admin/budgets`

```json
{"items":[{"id":1,"expected_revision":1,"budget":120,"ownerId":"owner@example.com"}]}
```

每项 id 为正整数且不重复；预算 revision 必须匹配。任意冲突整批 409，不存在或无效 Owner 422。返回 `{"updated_count":1}`，完全无变化的项不增加 revision，updated_count 只统计实际变化。预算/Owner 变更后需重新保存/同步；已存在的历史快照仍保留。

### PUT `/admin/config`

```json
{
  "expected_revision":0,
  "budgetReasons":[
    {"id":"reserve","label":"新增经销商预留","enabled":true},
    {"id":"unallocated","label":"无法分配到经销商","enabled":true},
    {"id":"other","label":"其他支出","enabled":true}
  ],
  "guide":{"text":"填写本轮预算分配指引"}
}
```

`expected_revision` 对应 workspace.state.configRevision。budgetReasons 和 guide 可各自省略；原因列表 1–30 项，id 以小写字母起始，仅含小写字母、数字、下划线或连字符，最长 64；label 非空最长 80；enabled 必须布尔值。仍被预算行使用的原因不能删除，可停用。guide.text 必须字符串；version 由后端递增，客户端提交值不会决定版本。

返回 `{revision,budgetReasons,budgetReasonVersion,guide,reference}`。revision 冲突 409，非法字典或删除使用中原因 422。

### POST `/admin/reference`

此接口**原子替换指定年度整批参考数据**，不是逐行合并。请求：

```json
{
  "expected_revision":1,"planning_year":2027,"batchId":"reference-20260923","asOf":"2026-09-23",
  "dealers":[{"id":"D001","name":"示例经销商","history":{
    "vol2024":100,"c32024":20,"vol2025":110,"c32025":22,
    "vol2026Ytd":80,"c32026Ytd":16,
    "resources2025":{"MRD":5,"SP&A":2,"ICE Rebate":1,"Capex":2}
  }}]
}
```

年度默认 2027、范围 2020–2100；batchId 最长 128，asOf 最长 32；dealers 非空且 id 不重复。history 只接收上述源字段，不接受 yield2025 等派生字段。数字可缺失/null，提供时须为有限非负数且小于 10^16；不把未知历史强行补零。id 最长 255，name 可省略。

返回 `{batchId,asOf,importedAt,planningYear,count,revision}`。配置 revision 过期 409；坏字段/重复对象 422，不产生半批数据。新批次使旧 Insight 的依据过期。

## 5. 百炼六点 Insight

Scope：Owner 使用 `owner:本人小写邮箱` 或 `initiative:预算ID`；负责人使用本部门代码（如 `MKT`），范围继续受 Sector 限制。管理层仅 GET `scope=global` 读取最新同步数据的六点预览，不调用模型，不允许改提示词或生成。管理员不访问业务 Insight。

负责人提示词按年度、部门共享，作为部门分析要求；生成的分析按调用邮箱保存和读取，并再次核对当前数据范围。权限或负责的 Initiative 范围变化时，不返回旧范围的分析。管理层预览使用最新快照金额及当前授权历史参考，依据批次随响应展示。

### GET `/insights?planning_year=2027&scope=owner%3Aowner%40example.com`

年度必填 2000–2100，scope 长度 1–300。返回：

```json
{"record":null,"prompt":{"scope":"owner:owner@example.com","text":"默认分析提示词","version":0,"editable":true}}
```

未生成时 record=null；历史结果存在时 record 含 `scope,status,signature,analysisMethodVersion,reference,guideVersion,createdAt,basisLabel,items,guideText,promptText,promptVersion,promptScope,disclaimer,stale`。`items` 恰为六点，key 为 `low_yield/high_yield/concentration/overlap/trend/completeness`，每点含 `finding,object,evidence,review,text,status`。无可比证据明确 limited，不编造零值。stale=true 表示工作稿、参考数据、指引或提示词等依据已变，应显示过期提示，不能当作新结果。

### PUT `/insights/prompt`

```json
{"scope":"owner:owner@example.com","planning_year":2027,"text":"按六点说明事实与复核方向","expected_version":0}
```

Owner/负责人仅修改本范围。text 非空，最长 12000；expected_version 非负，首次默认 0。返回 `{scope,text,version,editable}`；过期版本 409，空白文本 422。保存提示词不自动生成分析。

### POST `/insights/generate`

请求 `{"scope":"owner:owner@example.com","planning_year":2027}`。Owner/负责人允许；管理层、管理员 403。后端按权限取数并计算六项证据，单次调用百炼生成解释，然后持久化并返回完整 record。调用期间依据发生变化时返回 stale=true。

未配置 key/地址 503；HTTP、超时、JSON 格式或六项结构异常 502。失败不覆盖旧 record，不修改预算，不阻塞保存/同步。客户端显示失败后可继续读取旧分析。管理层预览不是一次真实百炼生成。

## 6. 保留的旧接口（已加入邮箱权限）

V1.4 页面草稿及 Excel 回传使用第 3 节整项保存；以下单行写接口不携带 expected_revision，保留兼容用途，每次写入仍更新预算修订号和已分配金额，因此可能使已打开的新版草稿发生 409。

### GET `/my-initiatives`

Owner/负责人可读；旧查询年度固定为 2027。可选 query：initiative_keyword（最长255）、resource_type_keyword（最长64）、status（0或1）。返回：

```json
{
  "current_user":{"user_id":"owner@example.com","user_name":"Owner","department":"MKT","sector":"B2C"},
  "initiatives":[{"id":1,"planning_year":2027,"sector":"B2C","department":"MKT","resource_type":"MRD","initiative":"渠道增长","budget":"100.00","allocate_budget":"100.00","status":0}],
  "responsible_budget":{"planning_year":2027,"initiative_count":1,"total_plan_budget_amount":"100.00"},
  "completion_progress":{"total_initiative_count":1,"completed_initiative_count":0,"pending_initiative_count":1}
}
```

### GET `/initiatives/{budget_id}/distributor-allocations`

Owner/负责人按范围可读，返回数组。单行结构：

```json
{"id":1,"distributor_code":"D001","allocate_amount":"80.00","rate":"0.8000","desc":"渠道投入"}
```

rate 为该行金额 / 总预算的小数比例，总预算零时为零，不是百分数字符串。

### POST `/initiatives/{budget_id}/distributor-allocations`

仅 Owner。请求 `{"distributor_code":"D001","distributor_budget_amount":80,"description":"渠道投入"}`。编码非空最长255，金额非负两位小数，说明可空最长255。校验经销商存在及不重复；成功返回新增单行。该接口追加一行，不覆盖已有列表。

### PATCH `/initiatives/{budget_id}/distributor-allocations/{allocation_id}`

仅 Owner。请求 `{"distributor_budget_amount":90,"description":"调整说明"}`，至少提供一个字段；可省略任一字段，description=null 清空说明。金额不能 null，禁止未知字段，不能改经销商编码。成功返回修改后的单行；记录不在本预算 404。

### DELETE `/initiatives/{budget_id}/distributor-allocations/{allocation_id}`

仅 Owner，无请求体，成功 `{"code":200,"msg":"删除成功","data":null}`。不存在 404。

### GET `/initiatives/{budget_id}/budget-summary`

Owner/负责人可读。返回 `{"budget_id":1,"initiative":"渠道增长","budget":"100.00","allocated_amount":"100.00","unexplained_difference":"0.00"}`。allocated_amount **包括经销商分配及其他预算**，差额=总预算−allocated_amount。

### GET `/distributor-allocation-template`

所有启用的工作台身份可调用。成功直接返回文件二进制，使用 Blob content type 及 `Content-Disposition` 文件名，不包 JSON。依赖 azure_blob_workbench_template_name 和 Blob 配置；模板不存在404，下载失败502，未配置503。

### POST `/initiatives/{budget_id}/distributor-allocations/import`

仅 Owner。multipart/form-data，字段 `file` 为 `.xlsx`，上限使用 azure_blob_max_upload_bytes（默认20MiB）。表头可用 `distributor_code,distributor_budget_amount,description`，中文表头为 `经销商编码/分配金额/说明`，金额也支持 `allocate_amount`，说明也支持 `desc`；三个表头均需存在。文件为空/无效/表头不全/重复编码/行金额错误400，超限413，未知编码422，编码已存在于当前预算409。整批校验通过才追加；任意错误回滚。成功 `{"imported_count":2}`。

**此接口是追加导入，不能用于“导出→修改→确认回传”，否则会产生重复冲突。新版 Excel 的修订号、差异预览和整项替换均走 PUT draft。**

## 7. 基础与测试接口

这些接口不使用工作台邮箱权限；测试接口不作为生产业务入口。

| 方法与完整路径 | 请求 | 成功 data |
|---|---|---|
| GET `/health` | 无 | `{status:"ok",service,version,environment}`；仅存活检查 |
| GET `/api/v1/test/ping` | 无 | `{message:"pong",environment,timestamp}` |
| POST `/api/v1/test/echo` | `{"message":"hello"}`，长度1–200 | `{"message":"hello"}` |
| GET `/api/v1/test/database-value` | 无 | data.test_table 的首个整数值；用于数据层至 Controller 链路验证 |

## 8. 最小联调示例

下列为开发邮箱和合成数据示例；必须先有对应权限/预算/经销商，不是初始化脚本：

```powershell
$base = 'http://127.0.0.1:8000/api/v1/workbench'
$headers = @{ 'X-User-Email' = 'owner@example.com' }
$workspace = Invoke-RestMethod "$base/workspace?planning_year=2027" -Headers $headers
$draft = Invoke-RestMethod "$base/initiatives/1/draft" -Headers $headers
$body = @{
    expected_revision = $draft.data.revision
    rows = @(@{ dealerId='D001'; amount=80; note='渠道投入' })
    otherBudgets = @(@{ reasonId='reserve'; amount=20; note='新增预留' })
} | ConvertTo-Json -Depth 8
$saved = Invoke-RestMethod "$base/initiatives/1/draft" -Method Put -Headers $headers -ContentType 'application/json; charset=utf-8' -Body ([Text.Encoding]::UTF8.GetBytes($body))
$publish = @{ expected_revision=$saved.data.revision; note='本轮同步' } | ConvertTo-Json
Invoke-RestMethod "$base/initiatives/1/publish" -Method Post -Headers $headers -ContentType 'application/json; charset=utf-8' -Body ([Text.Encoding]::UTF8.GetBytes($publish))
```

验收需覆盖同部门两个 Owner 隔离、负责人只读、草稿不平衡可保存/不可同步、同步后修改不影响管理层、过期 Excel 无部分写入、AI 失败保留旧结果。当前真实 PostgreSQL 连接及百炼调用尚待可达网络和本地 key 配置；不能把本地测试通过等同于远端验收。
