# Insight 投入比较与 300 家验收

## 交付行为

- 分配页提示：下载模板内含经销商列表及 Sector。
- Insight 增加完整投入核对表：经销商 × Sector × 资源类型，比较 2025 历史实际与本次计划，列出差额、倍数和复核原因。多项 Initiative 合并后只使用一次历史基数。授权历史中有记录、本范围没有分配行的对象也进入核对表。
- 复核项按规则计算，不依赖模型有没有选中、有没有写进摘要。完整表支持分页、状态筛选及名称/代码搜索；管理层使用最新同步快照，保持只读。
- 零实际与缺失分开；缺失、负数、业务线或资源口径不明确时不作可比判断。2025 与 2027 是跨年参考，不叫同比。资源类型历史实际不等于某一 Initiative 的精确历史投入。

## 规则与配置

| 条件 | 当前默认值 | 结果 |
| --- | --- | --- |
| 计划较实际增加 | 倍数 ≥ 2，且增加 ≥ 50,000 元 | 建议复核 |
| 计划较实际减少 | 计划/实际 ≤ 0.5，且减少 ≥ 50,000 元 | 建议复核 |
| 历史实际大于零、本范围计划为零 | 不要求已有分配行 | 建议复核 |
| 历史实际为零、计划大于零 | 倍数不可计算 | 新增投入事实 |
| 数据缺失或不可比 | 不填零、不推算历史 | 待补充信息 |

配置项为 `insight_investment_increase_multiple`、`insight_investment_decrease_multiple`、`insight_investment_absolute_change`。这些是第一版复核阈值，不代表业务已判定投入错误或应该增减预算。阈值随事实进入签名，变更会使旧分析过期。

## 模型输入与结果校验

仍使用 OpenAI-compatible messages + JSON Schema，事实采用列式 JSON 编码，重复说明共享。小输入保留全部事实；大输入发送全量汇总、最多 10 条投入比较和最多 16 家代表对象的相关计划、Yield、Vol/C3，优先覆盖复核类别及大额变化，再覆盖极值和象限。输入明确标记选中、省略数量，不能从例子推断剩余对象。

服务器保留完整授权证据、图表总体和核对名单，中位数及分母按全量计算。模型引用和文案数字先按实际发送事实检查，再按完整事实检查；不允许使用未发送对象。模型可解释事实，不能生成预算、扩大权限或修改配置。

实际运行的 `resource-investment-insight/SKILL.md` 和 `prompts/common.md` 已补充中文写作规则：具体对象、年份、实际金额、计划金额、变化和需确认事项；解释 Yield，避免空话及内部 JSON。三种方案共用。工程外独立源包和全局 Codex skill 未同步修改。

## 等待与失败

保持服务端总时限默认 60 秒、前端请求上限 65 秒。总时限覆盖模型调用、校验修复和保存。临时网络故障、429、502、503、504 在剩余时间允许时最多补一次传输重试；校验失败最多修复一次，均不延长总时限。认证、配置或不合法返回不会无条件重试。

失败保留上次成功结果，在面板中持续显示原因和重试入口；切换分析范围/方案后旧请求不能覆盖新范围。日志记录耗时、错误类别、校验诊断与安全请求编号，不记录请求密钥或提供方响应正文。

## 验收复现

在 backend 执行：

```powershell
.\.venv\Scripts\python.exe scripts/evaluate_insight_investment.py --output <新的输出目录>
.\.venv\Scripts\python.exe scripts/evaluate_insight_investment.py --output <另一个新的输出目录> --live
.\.venv\Scripts\python.exe -m pytest tests insight_capabilities/resource-investment-insight/tests -q -o addopts=''
```

`--live` 显式使用已配置开发模型，输入全部为合成数据。数据库及经销商目录均使用隔离 SQLite；不连接生产数据库或真实经销商目录。合成数据含 300 家：10 万→100 万、未分配、减投、实际为零、实际缺失，以及最后一条高额变化。程序验证 HTTP 生成、完整名单、复核状态和再次读取保存记录，并在输出目录保存可回放证据。

首轮真实调用发现新增投入事实关联、名称空格和减少金额表达的兼容问题，修复须通过真实候选回放及再次调用，不能把早期失败当成成功。
