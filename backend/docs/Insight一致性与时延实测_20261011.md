# Insight 一致性与时延实测 · 2026-10-11

本轮结论：应保留本地调整。真实工程链路中的正常场景已明显减少无依据风险和图文错配；最后冻结版本三个方案均一次生成通过，人工逐项复读未发现本轮所列反例。仍不能把小样本通过理解为任意自然语言或生产数据均零差错。

## 测试对象与输入

测试的是 `shell-resource` 实际 React 前端、FastAPI Controller / Service / Repository、权限过滤、证据构造、能力包、真实 Qwen、保存与回读链路。基线 main / origin/main 为 `621b15e2b657fb9f3e6df5c09f2f2cc96423847b`。实测完成时全部修改留在本地，没有提交、推送或部署；后续提交记录以 Git 为准。

数据使用隔离 SQLite 的合成 Owner 场景：1 项 Initiative、6 家经销商，并放入其他 Owner 的不可见项目以验证隔离。没有读写生产业务库。模型使用当前工程配置的 `qwen3.8-flash`、关闭 thinking、JSON Schema，凭据留在忽略配置中。

工程外 HTML 原型/人工能力包样例的输入由作者编写；此次模型输入由真实工程的授权工作台查询生成，含预算、逐家历史、变化量/比率、系统分组、数据集和六维检查约束。因此原型展示不能替代这次工程效果验证。SQLite 也不能证明生产 PostgreSQL 和大队列性能。

## 已调整的内容

1. 增加保存前一致性检查：状态与风险措辞、对象与具体指标引用、数字和分组、图表主题、未展示图表的文字引用、未预计算的“其余对象范围”。不通过时最多一次模型修复，仍失败则不保存，不覆盖旧结果。
2. 支持显式 `{{fact_id}}` 替换真实值；对明确提及的授权对象/指标补齐引用，逐项保留审计。只改引用与显式占位符，不能偷偷改结论、数字或状态使其通过。补上否定语义和群体引用，降低正确结果被误拦截的概率。
3. 图表标题采用数据集标题，图表说明由系统数据集呈现；模型额外解释放在独立 finding 并绑定事实。六维摘要始终保留，不把自由文案固定成六段模板。
4. 无损列式传输事实/图表行，合并重复口径，Schema 用 `$defs` 去重。没有裁掉经销商或遗漏 null/0/年份/范围。正常样本 99 条事实、7 组数据集，证据 JSON 从 42,827 降为 19,209 UTF-8 字节（约减少 55.1%），还原后与原证据完全相同。最终完整请求约 9.2k 输入 tokens；上一轮工程组约 17.6k。后者仅为阶段对比，新增派生事实和提示词也有变化，不是严格同一请求的 A/B 压缩率。
5. 按“质量优先，半分钟可接受”调整：后端整次保护上限 60 秒，包含必要修复；前端 65 秒兜底，显示已等待秒数。内部接收 SSE 后仍等完整校验通过才展示。未通过不输出半成品，也不靠截断 JSON 或删证据换取速度。

## 最后一轮实际结果

| 方案 | HTTP 完整返回 | 模型次数 | 输入 / 输出 tokens | 人工核验 |
|---|---:|---:|---:|---|
| 综合体检 | 15.88 秒 | 1 | 9157 / 651 | 通过本轮反例检查 |
| 历史 Yield × 计划投入 | 20.93 秒 | 1 | 9176 / 1001 | 通过本轮反例检查 |
| 分配结构分析 | 17.57 秒 | 1 | 9172 / 828 | 通过本轮反例检查 |

三次中位数 17.57 秒；这三次都没有触发修复。实际浏览器点击生成的独立一轮为 26.75 秒，等待提示、六维摘要、图表、保存回读正常，登录后当前页面控制台 0 错误。最后一轮 HTTP 25/25 检查通过，覆盖三个方案保存与切换回读、未知方案拒绝、越权读取拒绝、用户提示词不可编辑、管理层只读及预算未变。

异常场景的真实 Service 复测：缺说明 23.12 秒，明确要求补齐非零其他预算说明；零基期 17.75 秒，保留 Vol +100 / C3 +1000，不编造同比率；超额 24.33 秒，展开预算缺口；同 Yield 最后补测 20.41 秒，没有伪造高低差异。这些是在本轮迭代过程中产生的结果，已用最终校验器离线重放，不能误称均由最后提示词重新生成。

## 为什么前端那次是 26.8 秒

15.88 / 20.93 / 17.57 秒是最后一轮三个独立 HTTP 请求；26.7506 秒是此前浏览器发起的另一轮结构分析请求，不是同一次调用的前后端两种计时。浏览器那轮模型调用为 26.531 秒，证据准备为 0.120 秒，其余请求处理合计约 0.220 秒（含准备、校验、数据库与本地请求往返）；没有把纯 React 绘制耗时单独测出。

浏览器那轮输出 1,277 tokens，最后那轮结构分析输出 828 tokens，模型调用为 17.383 秒；输出长度和模型响应波动都影响总耗时。因此不能用 26.8 减 17.6 得出“前端额外花了 9.2 秒”，也不能把这几次不同调用当成严格 A/B 性能对比。

## 失败与人工复核发现也保留

- 正常重复测试中出现过一次 ConnectError，未取得模型结果；不能算质量通过。
- 早期 30 秒硬截止截断过零基期/超额请求，现已改为 60 秒质量保护窗口。
- 群体数量漏引用、否定句被误当作效率判断，分别导致正确候选被拒绝；已补测试并修正。阶段性 12 次 Service 记录原为 9 成功、3 失败；其中 11 次有完整候选。原始失败状态保留，最终规则离线重放另列，重放不是一次新的真实模型调用。
- HTTP 曾有一轮四象限在一次修复后仍返回 502，未保存；该次未保留候选正文，无法进一步区分模型错误和校验误拦截。后续本地合成 HTTP 复测增加显式诊断文件，避免再只看到通用错误。
- 一轮 HTTP 功能检查虽为 25/25，人工复读发现“详见图表”但页面无对应图，以及“其余五家占比 8.93%–16.07%”漏掉 19.64% 对象。最终校验器能拒绝这两条原始结果；更新后的真实 HTTP 三方案结果见上表。
- 所有中间候选、超时及原始结果都在 `.cache/insight-live/20261011-v4-*` 分阶段留存，没有用成功重测覆盖失败。修复调用会增加等待，迭代中两次调用出现过约 37–43 秒。不要用最后三次的最短值承诺上线 SLA。

## 验证与边界

后端 126 个测试、能力包 25 个测试、前端 72 个测试通过；前端 build 通过；修改范围 Ruff、两项服务 mypy、Git diff whitespace 检查通过。前端第一次全并发测试有一个无关 Excel worker 用例触发 5 秒超时，限制为 2 个 worker 后 72/72 通过。构建仍有既有大包提示，未扩大范围处理。

自动检查是针对已知业务规则和语言模式的防线，不是通用自然语言证明器；复杂比较、口径省略、因果暗示仍需抽检。正式验收还应覆盖真实规模数据、复杂多 Initiative 组合、Lead 部门范围及目标环境网络；本轮的真实模型主测范围为合成 Owner。当前没有证据表明必须换模型，优先保留证据契约、引用审计和失败保护，扩大数据规模与角色样本后再判断。
